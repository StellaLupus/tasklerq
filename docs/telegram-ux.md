# Telegram UX Tasklerq

## 1. Принципы

1. **Одно сообщение — один экран.** Навигация редактирует текущее сообщение, а
   не засыпает чат новыми.
2. **Кнопки внутри контента.** Основной интерфейс — RichMessage с
   `<tg-button>`; внешняя inline-клавиатура не используется.
3. **Быстрое добавление.** Свободный текст — главный способ ввода; форма —
   запасной.
4. **Ничего без подтверждения в боте.** LLM-черновик из Telegram применяется
   только после «Сохранить всё». Исключение — позиции покупок, добавленные
   текстом на экране списка покупок: они сохраняются сразу, а баннер даёт
   «↩️ Отменить» в течение 10 минут. Внешний capture в режиме `auto` создаётся
   сразу и в боте не подтверждается.
5. **Понятные ошибки.** Сообщение говорит, что исправить, и не показывает
   стектрейсы.
6. **Русский язык.** Даты, склонения и подписи — на русском.
7. **Доступность.** Статус передаётся текстом, а не только цветом.
8. **Одна строка элемента — одна кнопка.** В списках задач, «Моих задачах»,
   результатах поиска и покупках нет отдельных служебных кнопок в ряду
   элемента.
9. **Единая навигация.** «⬅️ Назад» есть на всех экранах, кроме меню и
   экранов первого контакта (`Welcome`, `FirstContact`). У самого редактора
   возврат — «✖ Отмена»; экран поля ведёт «⬅️ Назад» в редактор, а на первом
   поле создания «Название» есть и «✖ Отмена». Глубже двух переходов — ещё
   «🏠 Меню». Заголовок показывает путь хлебными крошками на экранах глубже
   двух переходов.
10. **Результат выполнения — баннер над экраном.** Выполнение задачи
    показывается баннером с кнопками над текущим экраном, а не отдельным
    экраном результата.
11. **Подписи действий без «Готово».** Смена статуса называется «✓ Выполнено»
    у задачи и «✓ Куплено» у покупки, закрытие мультивыбора — «Применить».

Текст маршрутизируется по активному экрану: на экране списка покупок он
добавляет позиции сразу, на списке задач уходит в разбор с этим списком, в
остальных местах — в общий разбор. Готовый черновик не заменяет чужой экран: на
нём появляется баннер «Черновик готов» с кнопкой «Открыть» (раздел 7).
Результат прямого добавления с черновиковой частью подчиняется тому же правилу:
на списке покупок остаётся список с баннером «Добавлено: … Черновик готов» и
кнопками «↩️ Отменить» и «Открыть», на чужом экране — баннер «Добавлено в
«Покупки»: …» и «Открыть»; карточка открывается экраном только когда активного
экрана нет, активен статус этого задания или карточка этого же черновика.

## 3. RichMessage

### Формат

Рендерер собирает HTML:

```html
<h3>Задачи · 12</h3>
<p>Просрочено: <b>2</b> · На сегодня: <b>4</b></p>

<tg-button-row>
  <tg-button type="callback_data" data="t:AbCdEfGhIjKlMnOp">➕ Добавить</tg-button>
  <tg-button type="callback_data" data="t:QrStUvWxYz012345">🛒 Покупки · 7</tg-button>
</tg-button-row>

<hr/>

<p><b>Просрочено</b></p>
<tg-button-row>
  <tg-button type="callback_data" data="t:...">Оплатить интернет · 18:00 · 🔴 срочно</tg-button>
</tg-button-row>

<p><b>Сегодня</b></p>
<tg-button-row>
  <tg-button type="callback_data" data="t:...">Позвонить маме · 19:00</tg-button>
</tg-button-row>

<tg-button-row>
  <tg-button type="callback_data" data="t:...">⬅️ Назад</tg-button>
  <tg-button type="callback_data" data="t:...">⚙️ Настройки</tg-button>
</tg-button-row>
```

Правила:

- не более 2–3 кнопок в ряду, чтобы текст не обрезался;
- callback_data — только `t:` + 16 символов; не более 64 байт;
- пользовательский текст экранируется (`&lt;`, `&gt;`, `&amp;`);
- длинные описания — свёрнутой цитатой `<blockquote expandable>`;
- таблицы — только для коротких сравнений (например, журнал), не для списков
  задач;
- эмодзи дополняют текст, но не заменяют его.

Точная JSON-схема `sendRichMessage` инкапсулирована в адаптере.

## 4. Экраны

### 4.1 Онбординг

#### Шаги формы

**Шаг 1. Приветствие**

```text
Привет! Я Tasklerq

Помогу вести задачи и покупки всей семьёй.

Как назовём ваше пространство? Отправьте название (до 100 символов).

Если вас пригласили, откройте ссылку-приглашение от владельца.
```

Пользователь вводит название (1–100 символов).

**Шаг 2. Часовой пояс**

```text
«Семья» — выберите часовой пояс

Нажмите кнопку или отправьте свой пояс текстом, например Asia/Novosibirsk.
```

Кнопки часовых поясов:

```text
[Москва (UTC+3)] [Санкт-Петербург (UTC+3)]
[Калининград (UTC+2)] [Самара (UTC+4)]
[Екатеринбург (UTC+5)]
[✖ Отмена]
```

Свой пояс вводится текстом как IANA-идентификатор; отдельной кнопки «Другой»
нет. Валидация: существует ли пояс.

**Шаг 3. Пространство создано**

```text
Пространство создано

Созданы списки «Задачи», «Покупки» и «Календарь».

Отправьте мне любую фразу — например: «завтра купить молоко и позвонить маме».
```

Кнопки: «📋 Открыть меню», «👥 Пригласить семью».

Повторный `/start` не создаёт второй household.

#### Первый контакт

До открытия формы бот классифицирует состояние инсталляции. В режиме
`TENANCY_MODE=multi` онбординг доступен всегда. В режиме `TENANCY_MODE=single`
(по умолчанию) таблица исходов:

| Состояние инсталляции | `BOOTSTRAP_OWNER_TELEGRAM_ID` | Экран |
| --- | --- | --- |
| household нет | не задан | Онбординг |
| household нет | равен отправителю | Онбординг |
| household нет | другой ID | «Пространство ещё не настроено» |
| один household, владелец есть | любой | «Это частное пространство» |
| один household, владельца нет | не задан или равен отправителю | Команда администратора с ID отправителя |
| один household, владельца нет | другой ID | «Пространство ещё не настроено» |
| больше одного household | любой | «Нужен администратор» |

Экраны информационные, без формы:

```text
Это частное пространство

Попросите приглашение у владельца.
```

```text
Пространство ещё не настроено

Владельца назначает администратор командой:

tasklerq admin user add --telegram-id <id> --role owner

Бот не назначает владельца сам.
```

```text
Пространство ещё не настроено

Обратитесь к администратору.
```

```text
Нужен администратор

Инсталляция требует вмешательства администратора.
```

Правила:

- ожидаемый Telegram ID из `BOOTSTRAP_OWNER_TELEGRAM_ID` не раскрывается: при
  чужом ID показывается нейтральный экран «Пространство ещё не настроено»;
- бот не назначает владельца сам и в режиме `single` не создаёт household, если
  он уже есть;
- успешное принятие `/start <code>` не зависит от состояния инсталляции; при
  отказе показывается баннер и экран по классификатору первого контакта
  (таблица выше). Уже состоящему участнику бот отвечает, что приглашение не
  нужно;
- если household создали, пока пользователь заполнял форму, а сам отправитель
  остался без записи, подтверждение пояса не создаёт второй household: форма
  закрывается, состояние перечитывается и показывается экран по таблице (обычно
  «Это частное пространство»);
- если пока форма была открыта отправителя добавили в household (например,
  `admin user add` или `household create --owner-telegram-id` с его ID), форма
  закрывается и показывается главное меню: онбординг уже не нужен.

### 4.2 Главное меню

```text
Семья
Просрочено: 2 · На сегодня: 4 · Выполнено: 3
Напишите задачу или покупку — я разберу.

[➕ Добавить] [🛒 Покупки · 7]
[📋 Задачи · 12] [👤 Мои задачи · 3]
[🗓 Повестка] [🔎 Поиск]
[⚙️ Настройки]
[🗂 Все списки]
```

- Заголовок — название household. Шапка показывает просроченные задачи,
  задачи и события на сегодня и выполненные сегодня. Событием на сегодня
  считается событие, которое начинается сегодня или началось раньше и ещё не
  прошло; прошедшие события в счётчик не входят.
- При ожидающем черновике Telegram над кнопками появляется строка с числом
  пунктов и кнопкой «Открыть»:

  ```text
  📝 Ждёт подтверждения: 2 пункта
  Напишите задачу или покупку — я разберу.

  [Открыть]
  ```

  Строка исчезает после сохранения, отмены или истечения черновика. Если в
  черновике не осталось пунктов, показывается «0 пунктов» (ограничение —
  раздел 14).
- Подсказка свободного текста зависит от разбора. С включённым LLM: «Напишите
  задачу или покупку — я разберу.» Без разбора: «Напишите название задачи —
  открою редактор задачи.»
- «📋 Задачи · N» — открытые задачи списка задач по умолчанию, «🛒 Покупки ·
  N» — открытые позиции списка покупок по умолчанию. Если список по умолчанию
  не помечен, берётся первый видимый список этого вида; если видимых списков
  этого вида нет — счётчик по всем открытым задачам или покупкам.
- «👤 Мои задачи · N» — открытые задачи, назначенные пользователю. То же число
  стоит в заголовке экрана «Мои задачи». Экран показывает не больше 50 строк
  (ограничение поиска `MAX_LIMIT`), а число в заголовке — полное.
- «🗓 Повестка» открывает первую страницу повестки (4.2.1).
- «🗂 Все списки» показывается при трёх и более видимых списках, не считая
  списков событий; два и более списков событий тоже показывают её. Отдельной
  строки «Списки: …» в меню нет.
- «🔎 Поиск» открывает ввод запроса, «⚙️ Настройки» — настройки.

После завершения задачи или покупки меню перерисовывается при возврате.

### 4.2.1 Экран «Повестка»

«🗓 Повестка» открывает события и открытые задачи со сроком всех видимых
списков household по дням. Окно — семь дней с сегодняшнего; «Дальше ▶»
открывает следующие семь дней, «◀ Раньше» — предыдущие, но не раньше
сегодняшнего. На первой странице кнопки «◀ Раньше» нет.

```text
Повестка

Просрочено
[☐ Оплатить интернет · вчера · 🟠 высокий]

Вторник, 10 ноя
[весь день Отпуск]
[14:00–15:30 Маникюр]
[☐ 16:00 Позвонить в банк]

Среда, 11 ноя
[18:00–19:00 Тренировка 🔁]

[➕ Событие]
[Дальше ▶]
[⬅️ Назад]
```

- Внутри дня вседневные элементы идут перед элементами со временем, а
  элементы со временем — по возрастанию времени начала.
- Прошедшие события и выполненные задачи не показываются. Многодневное
  событие показывается в каждом дне окна, который оно занимает, пока не
  прошло.
- Раздел «Просрочено» есть только на первой странице общей повестки; события
  в него не попадают.
- Повторяющийся элемент показывается на каждом своём вхождении в окне и
  помечен «🔁».
- На экране не больше 30 строк: лишние скрываются, ниже показывается
  «…и ещё N». «Просрочено» входит в тот же лимит, идёт первым и при
  переполнении вытесняет дни окна.
- Пустой экран сообщает: «На эти дни ничего не запланировано — добавьте
  событие.»
- Каждая строка — одна кнопка на всю ширину; тап открывает карточку элемента
  и не меняет его. Строка события подписана временем начала и конца
  («14:00–15:30 Маникюр») или «весь день», строка задачи — отметкой открытой
  задачи и сроком («☐ 16:00 Позвонить в банк»).
- «➕ Событие» открывает редактор нового события в списке событий по
  умолчанию, а в повестке одного списка — в этом списке. Свободный текст на
  экране повестки уходит в общий разбор, как на остальных экранах.
- Список событий на экране «Все списки» помечен «🗓», его счётчик считает
  только не прошедшие события, а тап открывает повестку этого списка с
  названием в шапке. Задачи в ней не показываются; «⬅️ Назад» возвращает в
  «Все списки».

### 4.3 Список задач

Заголовок: название списка, число открытых задач и, если за сегодня есть
выполнения, счётчик «✅ N» на каждой странице:

```text
Задачи · 9 · ✅ 1
```

Секции открытых задач:

1. **Просрочено** — сначала.
2. **Сегодня**.
3. **Завтра**.
4. **Позже**.
5. **Без срока**.

Каждая строка — одна кнопка на всю ширину: название, срок и только
«срочно»/«высокий». Исполнителя и отдельного чекбокса в строке нет.

```text
Оплатить интернет · сегодня, 18:00 · 🟠 высокий
```

Тап по строке открывает карточку задачи и не меняет её; «⬅️ Назад» из
карточки возвращает на ту же страницу списка.

Под открытыми задачами показывается число выполненных ранее: «Выполнено: N»,
а если открытых задач нет — «Выполнено ранее: N».

Последним разделом списка идёт «Выполнено сегодня»: задачи этого списка,
выполненные в текущий календарный день в часовом поясе пользователя. Раздел
виден на последней странице, а счётчик «✅ N» — в шапке на каждой странице.
Строка показывает время выполнения и открывает карточку с «↩️ Вернуть»: у
задачи без повторения возвращается выполнение, у повторяющейся — последнее
выполнение вхождения, пока задачу не меняли после него.

```text
Выполнено сегодня
✅ Вынести мусор · 13:47
```

Повторяющаяся задача показывается и открытой со следующим сроком, и в
разделе «Выполнено сегодня».

Если список открыт с экрана «Все списки», «⬅️ Назад» ведёт обратно в «Все
списки», а заголовок показывает путь «Все списки › Задачи · N». Список,
открытый из меню, возвращает в меню.

Подсказка ввода на экране списка задач показывает, куда добавится текст:

```text
Задачи · 0

Пока нет задач
Напишите — добавлю в «Задачи»

[➕ Добавить] [⬅️ Назад]
```

Текст уходит в разбор с этим списком как списком по умолчанию
(`default_list_id`): задачи без явно названного списка попадают сюда. Без
разбора бот открывает редактор задачи с этим списком.

Кнопки: «➕ Добавить», «📜 История», пагинация по 8 элементов и «⬅️ Назад».
Фильтров и сортировки в боте нет (см. раздел 14).

После «✓ Выполнено» в карточке бот возвращает в список, из которого открыта
карточка, с баннером «✅ Выполнено: <название>» и кнопкой «↩️ Отменить». Для
повторяющейся задачи баннер показывает следующий срок: «Следующее: …».
Отдельного экрана результата выполнения нет. Карточка задачи описана в 4.4.

### 4.3.1 Журнал выполнений

«📜 История» на экране списка задач (у покупок её нет) открывает журнал
выполнений всего household. Это не «📜 Журнал» настроек: там события
членства.

```text
Задачи › История

Пятница, 7 ноя (впереди)
[Сдать отчёт · Мария]

Среда, 5 ноя
[Оплатить интернет · Алексей]

Вторник, 4 ноя
[Полить цветы · Мария]
[Вынести мусор · Алексей]

Без срока
[Позвонить маме · Алексей]

[⬅️ Назад]
```

- Группы — по плановому дню выполнения в часовом поясе пользователя, от
  поздних к ранним; внутри дня записи идут от поздних по факту. День позже
  сегодняшнего подписан «(впереди)».
- Выполнения без срока идут последней группой «Без срока».
- Запись — кнопка «название · исполнитель», она открывает карточку задачи с
  контекстом этого выполнения. «Назад» из карточки возвращает в журнал на ту
  же страницу.
- На странице 8 записей; листание — «←» и «→», «⬅️ Назад» возвращает на
  список задач. Пустой журнал показывает «Пока нет выполнений.».
- Журнал строится из событий `completed`: поздние правки задачи уже
  записанные выполнения не меняют, а удалённые задачи и отменённые выполнения
  в журнал не попадают.
- Журнал ведётся только по задачам. «✓ Куплено» тоже пишет событие
  выполнения, но текущий список покупки — не список задач, поэтому покупки в
  журнал не попадают.

### 4.4 Карточка задачи

Карточка — экран просмотра. Тело показывает по порядку: пометку «✅ Выполнено»
у выполненного элемента, количество у покупки, срок (у просроченной задачи —
с пометкой «· просрочено»), приоритет у задачи, теги, исполнителя, правило
повторения со следующим вхождением, подзадачи с отметками, список и описание.
Описание — цитата: короткое обычной, длинное — свёрнутой
(`<blockquote expandable>`).

```text
Задачи › Оплатить интернет

📅 Сегодня, 18:00
Приоритет: 🟠 Высокий
🏷 дом, финансы
👤 Алексей
🔁 Каждый месяц, 5-го
Следующее: сб, 5 дек, 18:00
🧩 Подзадачи: 1 из 2
☐ Найти договор
☑ Позвонить в банк
Список: Задачи
> Оплатить до конца дня.

[✓ Выполнено] [📅 Срок]
[✏️ Править] [🗑 Удалить]
[⬅️ Назад] [🏠 Меню]
```

Отдельных кнопок полей («Приоритет», «Теги», «Подзадачи») в карточке нет:
все поля правятся в едином редакторе, который открывает «✏️ Править».

Для повторяющейся задачи:

- показывается правило и следующее вхождение;
- завершение переносит срок, а не удаляет задачу;
- «Удалить» удаляет всю серию (с подтверждением).

У выполненной задачи карточка начинается с «✅ Выполнено», а вместо статусной
кнопки и «📅 Срок» показывает «↩️ Вернуть», «✏️ Править» и «🗑 Удалить».

Карточка покупки показывает количество, исполнителя, список и заметку;
кнопки — «✓ Куплено», «✏️ Править» и «🗑 Удалить». У купленной позиции —
«✅ Выполнено» и «↩️ Вернуть».

После завершения:

```text
✅ Выполнено: Оплатить интернет
Следующее: сб, 5 дек, 18:00

[↩️ Отменить]
```

Это баннер над экраном, из которого открыта карточка; отдельного экрана
результата нет. У покупки кнопка называется «✓ Куплено», после неё бот
показывает список и тост «Отмечено: <название>».

#### Карточка события

Карточка события — экран просмотра. Тело показывает начало и конец, участника
(«👤 Чьё событие»), теги, правило повторения со следующим вхождением, список и
заметку; приоритета, подзадач и количества у события нет.

```text
Календарь › Маникюр

📅 Начало: Завтра, 14:00
🏁 Конец: Завтра, 15:30
🏷 салон
👤 Чьё событие: Маша
🔁 Каждую неделю: вт
Следующее: вт, 17 ноя, 14:00
Список: Календарь
> Мастер Ирина.

[📅 Перенести] [✏️ Править]
[🗑 Удалить]
[⬅️ Назад] [🏠 Меню]
```

- Кнопки «✓ Выполнено» в карточке события нет. Устаревшая кнопка отвечает
  «Событие нельзя выполнить.» и не меняет событие.
- «📅 Перенести» открывает экран быстрого срока «Срок»: «Сейчас: …» и кнопки
  «Сегодня», «Завтра», «+1 неделя» и «📅 Дата и время». Варианта «Без срока»
  у события нет.
- Быстрый срок сохраняет время суток и длительность события: «Завтра» у
  события «сегодня, 14:00–15:30» даёт «завтра, 14:00–15:30». У повторяющегося
  события меняется только ближайшее вхождение, а следующие идут по правилу
  серии.
- После переноса карточка показывает баннер «Начало: …». Устаревшая версия не
  сохраняется: бот показывает «Данные уже изменились. Показываю актуальное
  состояние.» и актуальную карточку.
- «🗑 Удалить» удаляет всю серию (с подтверждением), как у задачи.

#### Выполнения

Под телом карточки задачи, у которой есть выполнения, идёт свёрнутая цитата
«Выполнения»: до пяти последних выполнений, от поздних к ранним. Строка —
план → факт, исполнитель и отклонение от плана:

```text
Выполнения
> вт, 4 ноя → чт, 6 ноя, 13:47 · Мария · +2 дня
> ср, 5 ноя → ср, 5 ноя, 18:10 · Алексей
```

Отклонение считается в часовом поясе пользователя (раздел 10):

- срок без времени сравнивается по местным датам: тот же день — без пометки,
  более поздний — «+2 дня» с склонением, более ранний день — «раньше»;
- срок со временем: в более ранний день — «раньше»; раньше в тот же день или
  опоздание меньше часа — без пометки; от часа до суток — «+N ч»; от суток —
  целые дни вниз: «+1 день», «+2 дня», «+5 дней».

«↩️ Вернуть» в карточке выполненной задачи возвращает последнее выполнение:

- в карточке из журнала или «Выполнено сегодня» кнопка есть, только если
  открыто последнее выполнение, а задача не менялась после него; исключение —
  выполненная задача без повторения, у неё возврат прежний;
- в карточке без контекста выполнения (из поиска или списка) у выполненной
  задачи без повторения кнопка есть всегда — в том числе когда событий
  выполнения в журнале уже нет, тогда работает прежний возврат в работу; у
  повторяющейся и у открытой задачи (например, после снятия повторения) кнопка
  есть, только пока задача не менялась после последнего выполнения;
- возврат ставит задачу в `open`, восстанавливает срок и отметку выполнения
  (кто и когда выполнил) из снимка до выполнения, а у повторяющейся — ещё и
  слот перенесённого вхождения; запись исчезает из журнала и «Выполнено
  сегодня»;
- устаревшая кнопка (задачу изменили после отрисовки карточки) ничего не
  меняет и показывает «Данные уже изменились. Показываю актуальное
  состояние.».

#### Быстрый срок

«📅 Срок» в открытой карточке задачи открывает выбор:

```text
Задачи › Позвонить маме › Срок

Сейчас: сегодня, 18:00

[Сегодня] [Завтра]
[+1 неделя] [📅 Дата и время]
[Без срока]

[⬅️ Назад] [🏠 Меню]
```

- «Сегодня», «Завтра» и «+1 неделя» сохраняются сразу, без «Сохранить», и
  возвращают в карточку с баннером «Срок: …». «+1 неделя» считается от
  текущего срока, но не раньше сегодня; у задачи без срока — от сегодня.
- Время суток у задачи со временем сохраняется: «Завтра» у срока «сегодня,
  18:00» даёт «завтра, 18:00». Вседневный срок остаётся вседневным.
- «Сегодня» тоже сохраняет время суток, даже если оно уже прошло: срок сразу
  становится просроченным, и карточка показывает «· просрочено».
- «📅 Дата и время» принимает дату и время текстом: «завтра», «чт 12:00»,
  «25.12», «25.12.2026», «25.12 18:30» или только «18:30». Короткий день
  недели выбирает ближайший такой день, включая сегодня; если это сегодня и
  время уже прошло, ввод отвергается так же, как «сегодня 09:00». Дата без
  времени даёт вседневный срок.
- «Без срока» снимает срок и показывает баннер «Срок снят». У повторяющейся
  задачи этой кнопки нет.
- Устаревшая версия не сохраняется: бот показывает «Данные уже изменились.
  Показываю актуальное состояние.» и актуальную карточку.

У повторяющейся задачи переносится только текущее вхождение: правило и якорь
серии не меняются, а следующие вхождения идут со временем суток серии. Поэтому
«📅 Дата и время» → «чт 12:00» у задачи «каждый вторник 9:00» после выполнения
даёт следующий вторник 9:00, а не 12:00. Следующее вхождение считается по
правилу с учётом исходной даты перенесённого вхождения, поэтому перенос раньше
срока и повторный перенос не задваивают вхождение. Например, у задачи «каждый
месяц, 5-го» вхождение 5 ноября, перенесённое на 7 ноября, после выполнения
даёт 5 декабря.

После удаления (задачи и покупки):

```text
🗑 Удалено: Оплатить интернет

[↩️ Отменить] [⬅️ Назад] [🏠 Меню]
```

«↩️ Отменить» возвращает элемент в список в течение 10 минут с сообщением
«Возвращено: <название>»; после окна показывается «Время отмены истекло»,
элемент остаётся удалённым. «⬅️ Назад» возвращает в список без отмены; на
экранах глубже двух переходов рядом есть «🏠 Меню».

### 4.5 Создание и редактирование

Создание и правка идут через один редактор. Значения полей показаны текстом,
у каждого поля своя кнопка; выбор или ввод возвращает в редактор. Изменения
применяются только по «💾 Сохранить», а «✖ Отмена» не меняет элемент.

```text
Задачи › Карточка › Оплатить интернет

Название: Оплатить интернет
Срок: Сегодня, 18:00
Приоритет: 🟠 Высокий
Теги: дом
Подзадачи: Найти договор
Повторение: нет
Описание: —
Исполнитель: —
Список: Задачи

[📅 Срок] [🔴 Приоритет]
[👤 Исполнитель] [🏷 Теги]
[🧩 Подзадачи] [🔁 Повторение]
[📝 Описание] [📋 Список] [✏️ Название]
[💾 Сохранить]
[✖ Отмена] [🏠 Меню]
```

«🏠 Меню» внизу есть только на экранах глубже двух переходов от меню: у
редактора, открытого прямо из меню, этой кнопки нет.

У покупки набор полей другой: название, количество, единица, заметка,
исполнитель и список. Поля выбора закрываются сразу, а мультивыбор (теги,
подзадачи, дни недели) — кнопкой «Применить». Повторение настраивается на
одном экране: частота, дни недели, правило месяца и интервал.

#### Создание

- «➕ Добавить» в меню открывает поле «Название» («Как назвать задачу?»), затем
  редактор со списком задач по умолчанию. «📋 Список» показывает все неархивные
  списки household и переключает тип; несовместимые поля сбрасываются.
- «➕ Добавить» в списке задач или покупок открывает то же поле, но тип и список
  уже известны; у покупки вопрос — «Что купить?». Кнопка «📋 Список» и здесь
  может сменить тип.
- На первом поле создания «⬅️ Назад» работает как отказ, рядом есть
  «✖ Отмена».

#### Правка

«✏️ Править» в карточке открывает редактор с текущими значениями. Поля копятся
в черновике, а «💾 Сохранить» записывает их одной операцией: одно увеличение
версии, одно событие, и только те поля, которые пользователь менял
(`touched`). До сохранения элемент остаётся прежним. У существующего элемента
«📋 Список» предлагает только списки того же типа: перенос между задачами и
покупками не делается.

Если с момента открытия редактора другой участник изменил то же поле,
показывается экран конфликта с обоими значениями:

```text
Конфликт при сохранении

Срок:
Мой: Завтра, 18:00
Сейчас: пт, 20 ноя, 18:00

[Оставить мой] [Оставить текущий]
[⬅️ Назад] [🏠 Меню]
```

«Оставить мой» записывает значение из редактора, «Оставить текущий» оставляет
значение из базы. Изменения других полей сохраняются без вопроса; «⬅️ Назад»
возвращает в редактор, ничего не записывая. Повторение сравнивается без слота
перенесённого вхождения. Как и в редакторе, «🏠 Меню» на экране конфликта есть
только при глубине больше двух переходов от меню.

Срок в редакторе — обычная смена серии: у повторяющейся задачи переякоривается
серия и меняется время суток следующих вхождений. День недели еженедельной
серии задаёт «🔁 Повторение», а не поле «Срок». Чтобы перенести только текущее
вхождение, служит «📅 Срок» в карточке.

«✖ Отмена» закрывает редактор без изменений и возвращает на прежний экран. При
ошибке редактор остаётся открытым с пояснением и сохраняет введённые значения.

Валидация:

- пустое название → «Название не может быть пустым.»;
- прошедший срок при создании → «Срок уже прошёл.»; при правке такого
  сообщения нет: ошибки домена дают «Проверьте введённые значения.»;
- дата в прошлом при вводе → «Дата уже прошла.»;
- сегодняшнее время уже прошло → «Это время сегодня уже прошло.»;
- неразобранный срок → «Не понял срок.» с примерами формата;
- 11-й тег → «Можно не больше 10 тегов.»;
- 51-я подзадача → «Можно не больше 50 подзадач.»;
- интервал вне 1–365 → «Интервал — число от 1 до 365.»;
- ошибка валидации при сохранении → «Проверьте введённые значения.»
  (у создания — «Не получилось сохранить: проверьте введённые данные.»).

#### Событие

Событие создаётся и правится тем же редактором. Его поля: название, список
событий, начало, конец, повторение, чьё событие, теги и заметка. Полей
приоритета, подзадач, количества и единицы в нём нет. «📋 Список» у события
предлагает только списки событий.

```text
Календарь › Карточка › Маникюр

Название: Маникюр
Начало: Завтра, 14:00
Конец: Завтра, 15:30
Повторение: нет
Теги: салон
Заметка: —
Чьё событие: Маша
Список: Календарь

[📅 Начало] [🏁 Конец]
[🔁 Повторение] [👤 Чьё событие]
[🏷 Теги] [📝 Заметка]
[📋 Список] [✏️ Название]
[💾 Сохранить]
[✖ Отмена] [🏠 Меню]
```

- «📅 Начало» открывает «Когда начало?» с кнопками «Сегодня», «Завтра»,
  «📅 Дата и время»; варианта «Без срока» у события нет. «🏁 Конец» открывает
  «Когда конец?» с «📅 Дата и время» и «Без конца».
- Конец того же вида, что начало: вседневному событию задаётся дата, событию
  со временем — время. Время без даты в поле «Конец» относится ко дню начала,
  а если оно не позже времени начала — к следующему дню: при начале
  11 ноября 14:00 «15:30» даёт 11 ноября 15:30, а при начале 23:00 «01:00» —
  12 ноября 01:00.
- Сохранение без начала отклоняется с пояснением «Укажите начало события.», а
  редактор остаётся открытым. «Конец раньше начала.» тоже не сохраняется.
  Прошедшее начало при создании отклоняется как «Начало уже прошло.».
- Вседневному событию время конца не подходит («У события без времени конец
  задаётся датой.»), а событию со временем — дата без времени («Для события
  со временем укажите время конца.»).
- Если начала ещё нет, «Конец» можно открыть до «Начало»: значение сохранится
  в черновике и применится после выбора начала.
- После «💾 Сохранить» событие создаётся, а бот возвращается в повестку, из
  которой открыт редактор.

При сохранении покупки с названием уже открытой позиции бот не создаёт
дубликат, а предлагает «➕ Увеличить до …» или «📄 Добавить отдельно»; до
выбора позиция не создаётся.

**Быстрая форма после недоступного разбора.** Если разбор был включён, но
свободный текст не удалось разобрать, открывается тот же редактор с исходным
текстом в названии и списком задач по умолчанию; «📋 Список» переключает тип
так же, как при создании из меню. Баннер объясняет, что автоматический разбор
недоступен (или называет другую причину). Если разбор выключен, редактор
открывается сразу, без баннера.

Редактор живёт 15 минут. По истечении бот показывает «Правка устарела» /
«Начнём заново?» с кнопкой возврата на карточку, в список или в меню.
Сохранённое состояние прежних форм создания и правки тоже считается истёкшим.

### 4.6 Покупки

```text
Покупки · 2

Купить
☐ Молоко · 2 л
☐ Хлеб · 1 шт

Куплено
☑ Яйца · 10 шт

[➕ Добавить] [🧹 Очистить] [✏️ Править]
[🔎 Поиск] [⬅️ Назад]
```

Каждая строка — одна кнопка-переключатель на всю ширину: «☐» у открытой
позиции и «☑» у купленной, затем название и количество. Отдельной служебной
кнопки в строке нет.

- В обычном режиме тап по строке отмечает позицию купленной или возвращает её
  в список. Бот остаётся на экране списка, а после покупки показывает тост
  «Отмечено: <название>».
- «✏️ Править» включает режим правки: заголовок становится «Покупки · правка»,
  а тап по строке открывает карточку позиции. Подпись переключателя меняется на
  «✓ Закончить правку» и занимает отдельный ряд: она длиннее соседних и в ряду
  из трёх обрезается на узком Android-экране.

  ```text
  [➕ Добавить] [🧹 Очистить]
  [✓ Закончить правку]
  [🔎 Поиск] [⬅️ Назад]
  ```

  Карточка возвращает в список в том же режиме; выход из режима кнопкой или
  уход с экрана возвращает обычный режим. Вход в список другим путём (из меню
  или «Все списки») всегда открывает обычный режим.

Подсказка ввода на экране списка:

```text
Напишите — добавлю в «Покупки»
```

Без разбора подсказка уточняет формат: «Напишите — добавлю в «Покупки» (через
запятую или с новой строки)».

Текст на экране покупок добавляет позиции в этот список сразу, без карточки
черновика. Пока идёт разбор, список остаётся на месте с баннером «Добавляю…».
После разбора:

```text
Добавлено: Молоко · 2 л, Хлеб
[↩️ Отменить]

Покупки · 2

Купить
☐ Молоко · 2 л
☐ Хлеб · 1 шт

[➕ Добавить] [🧹 Очистить] [✏️ Править]
[🔎 Поиск] [⬅️ Назад]
```

- «↩️ Отменить» мягко удаляет только созданные позиции; окно — 10 минут от
  создания. Отменить может автор или владелец household. После окна баннер
  «Время отмены истекло», повторная отмена — «Добавление уже отменено».
  Отмена не уводит с чужого экрана (например, карточки задачи): он остаётся с
  баннером, а список перерисовывается, только если открыт он. В любом исходе —
  «Добавление отменено», «Время отмены истекло» или «Добавление уже отменено» —
  в баннере остаётся «Открыть» ожидающего черновика того же добавления.
- Если пользователь ушёл с экрана, список не заменяется: на текущем экране
  появляется баннер «Добавлено в «Покупки»: Хлеб». Если в тексте была
  черновиковая часть, баннер дополняется «Черновик готов» и кнопкой «Открыть»;
  это же работает, когда открыт редактор.
- Элементы другого типа (задачи, чек-лист) и невалидная покупка в список не
  попадают: они уходят в черновик. Результат подчиняется правилу позднего
  результата: на списке покупок остаётся список с баннером «Добавлено: …
  Черновик готов» и кнопками «↩️ Отменить» и «Открыть»; на чужом экране экран
  не заменяется, а получает баннер «Добавлено в «Покупки»: …» и «Открыть»;
  карточка открывается экраном только когда активного экрана нет, активен
  статус этого задания или карточка этого же черновика. Покупки к этому
  моменту уже сохранены.
- Дубликат не сохраняется. Баннер показывает «Уже в списке: «Молоко».» и выбор
  «➕ Увеличить до 3 л» / «📄 Добавить отдельно»; остальные позиции текста уже
  добавлены:

  ```text
  Добавлено: Хлеб Уже в списке: «Молоко».
  [➕ Увеличить до 3 л] [📄 Добавить отдельно] [↩️ Отменить]

  Покупки · 2

  Купить
  ☐ Молоко · 2 л
  ☐ Хлеб · 1 шт
  ```

  После выбора баннер заменяется результатом, но «↩️ Отменить» остаётся для
  позиций, созданных исходным добавлением. Позиция «📄 Добавить отдельно» в
  отмену не входит, а увеличенное количество существующей позиции отмена не
  откатывает. Кнопка «Открыть» ожидающего черновика остаётся отдельным
  последним рядом.
- Без LLM или при сбое разбора текст делится по запятым и переводам строк;
  каждая часть становится позицией с количеством 1, а баннер сообщает, что
  количество не распознаётся. Части, не прошедшие проверку (например, слишком
  длинное название), перечисляются после «Не добавлено (слишком длинное
  название): …». Если частей больше 20, бот ничего не создаёт и просит
  разделить текст.
- Если разбор вернул больше 20 элементов, текст не делится: бот сообщает, что
  элементов больше 20, и пользователь разделяет его сам (раздел 14).

Добавление и правка идут через единый редактор (см. 4.5): «➕ Добавить» в списке
покупок сразу открывает поле «Что купить?», затем редактор с полями:

- название;
- количество (по умолчанию 1);
- единица (по умолчанию «шт»);
- заметка;
- исполнитель (опционально);
- список.

Из меню «➕ Добавить» создаёт задачу в списке задач по умолчанию; чтобы добавить
покупку, переключите тип кнопкой «📋 Список».

Карточка позиции в режиме правки — экран просмотра:

```text
Покупки › Молоко

Количество: 2 л
👤 Алексей
Список: Покупки
> Безлактозное

[✓ Куплено] [✏️ Править]
[🗑 Удалить]
[⬅️ Назад] [🏠 Меню]
```

У купленной позиции вместо «✓ Куплено» — «↩️ Вернуть»; «✏️ Править» и
«🗑 Удалить» остаются.

Дубликат при сохранении через редактор:

```text
«Молоко» уже есть в списке (2 л).

[➕ Увеличить до 3 л] [📄 Добавить отдельно]
[✖ Отмена]
```

Очистка:

- если выполненных >5 — подтверждение «Удалить 6 позиций?»;
- после — «Отменить» на 10 минут.

Одиночное удаление позиции с карточки показывает экран «🗑 Удалено» с кнопками
«↩️ Отменить», «⬅️ Назад» и «🏠 Меню» (глубина 3), как в 4.4.

### 4.7 Поиск

```text
Что ищем?
```

Пользователь вводит текст. Результаты:

```text
Найдено 3 результата

Молоко · Покупки · 2 л
Молоко · Дача
✅ Купить молоко · Задачи · выполнено

[Открытые] [Выполненные] [Все]
[✏️ Изменить запрос] [⬅️ Назад]
```

Каждая строка — одна кнопка, которая открывает карточку. У выполненной записи
статус передан пометкой «✅» и словом «выполнено».

В боте доступен фильтр по статусу: «Открытые», «Выполненные», «Все». Фильтры
по списку, исполнителю и тегу в боте не реализованы (см. раздел 14); API
`GET /api/v1/search` их поддерживает. Поиск ищет по названию, описанию, тегам и
подзадачам.

### 4.8 Настройки

```text
Настройки

👤 Алексей
🌍 Часовой пояс: Europe/Moscow
Роль: владелец

[👤 Профиль] [🔔 Уведомления]
[⚠️ Опасное]
[👥 Семья] [📜 Журнал] [🔌 Интеграции]
[⬅️ Назад]
```

Экран показывает имя, часовой пояс и роль. Сводки уведомлений и опасных кнопок
на нём нет: они в «Уведомлениях» и «⚠️ Опасном».

«👤 Профиль» объединяет имя и часовой пояс:

```text
Настройки › Профиль

👤 Алексей
🌍 Часовой пояс: Europe/Moscow

[✏️ Имя] [🌍 Часовой пояс]
[⬅️ Назад] [🏠 Меню]
```

«✏️ Имя» принимает новое имя. «🌍 Часовой пояс» открывает «Настройки › Профиль ›
Часовой пояс»: предлагаемые пояса и «Как в пространстве»; выбор возвращает в
профиль. Экран уведомлений описан в 4.10.

«⚠️ Опасное» — отдельный экран. Владельцу доступно «🗑 Удалить пространство» с
подтверждением; участнику — «🚪 Выйти» с подтверждением «Выйти из
пространства?». «Семья», «Журнал» и «Интеграции» видит только владелец;
участник не видит кнопок, а прямой переход отклоняется.

#### Экран «Интеграции»

Доступен только владельцу: кнопка **🔌 Интеграции** есть в настройках у роли
`owner`. Участник кнопки не видит, а прямой переход и устаревшая кнопка
отклоняются.

```text
Интеграции

🔑 Home Assistant · tlq_ab12cd34
Области: ha:read, ha:write, capture:write
Последнее использование: сегодня, 18:20

[🚫 Отозвать «Home Assistant tlq_ab12cd34»]

Страница 1 из 2
[←] [→]

[➕ Выпустить токен для HA] [⬅️ Назад]
```

- Показываются активные токены household: имя, префикс, области действия и
  последнее использование. Отозванные и истёкшие не показываются. Если
  активных нет — «Активных токенов нет.».
- Список постраничный, по `PAGE_SIZE` токенов на страницу, как в других
  списках бота. Кнопки **←** и **→** листают страницы, подпись «Страница N из
  M» показывается при нескольких страницах. Страница за пределами открывает
  последнюю существующую. Кнопки выпуска и «Назад» есть на каждой странице.
- Последнее использование — «Последнее использование: сегодня, 18:20» или
  «не использовался».
- **➕ Выпустить токен для HA** создаёт токен «Home Assistant» с областями
  `ha:read`, `ha:write`, `capture:write` без срока действия. Экран
  перерисовывается на месте и сразу показывает новый токен по префиксу на
  первой странице.
- **🚫 Отозвать «… …»** открывает подтверждение:

```text
Отозвать токен «Home Assistant» (tlq_ab12cd34)?

Интеграция, которая им пользуется, перестанет работать.

[Отозвать] [Отмена]
```

После отзыва показывается баннер «Токен отозван.» и обновлённый экран с первой
страницы; если токен уже был отозван — «Токен уже отозван.». Следующий
API-запрос с отозванным токеном получает `401`.

**Сообщение с токеном.** Выпуск присылает отдельное сообщение: значение под
спойлером, строка «Сообщение удалится через час» и кнопка **Я сохранил**:

```text
<tg-spoiler>tlq_…</tg-spoiler>
Сообщение удалится через час

[Я сохранил]
```

- **Я сохранил** ставит удаление этого сообщения в outbox и показывает
  «Сообщение удалено.»; экран «Интеграции» не перерисовывается. Кнопка доступна
  любому получателю сообщения, в том числе бывшему владельцу: роль `owner` не
  проверяется.
- Если кнопку не нажимали, сообщение удаляется автоматически через час после
  доставки, а не после постановки в очередь.
- Сообщение с токеном засыпает якорь, поэтому следующий экран придёт новым
  сообщением (правило 0003, §6).

### 4.10 Уведомления

#### Экран настроек уведомлений

Открывается из «Настроек». Функции собраны блоками через черту; в начале
блока — текущее состояние. Уточняющие кнопки (время, lead time, границы)
показываются только у включённой функции, а переключатель называет действие
(«Вкл»/«Выкл»), а не текущее состояние.

```text
Настройки › Уведомления

🔔 Напоминания: за 15 минут
[⏱ За 15 минут] [Выкл]
[без времени — в 09:00]
────────────────────────
🌅 Утренняя сводка: 08:30
[🕗 Время сводки: 08:30] [Выкл]
────────────────────────
👤 О назначениях: вкл
[Выкл]
────────────────────────
🌙 Тихие часы: 22:00–08:00
[Начало тихих: 22:00] [Конец тихих: 08:00]
[Выкл]

[⬅️ Назад] [🏠 Меню]
```

- Выключенная функция показывает «…: выкл» и только кнопку «Вкл»; кнопок
  времени и границ у неё нет.
- «⏱ За 15 минут» открывает «Настройки › Уведомления › За сколько напоминать?»:
  кнопки «5 мин», «15 мин», «30 мин», «60 мин» и «Своё…». Выбор возвращает на
  экран уведомлений.
- «без времени — в 09:00» — время напоминания о задачах без срока; отдельного
  «Вседневного» напоминания нет.
- Времена вводятся в формате `HH:MM` (начало и конец тихих часов не могут
  совпадать); при ошибке бот показывает подсказку и оставляет прежнее значение.
- Изменения применяются со следующего тика планировщика и только к своему
  пользователю. Отложенные тихими часами уведомления не теряются:
  напоминание и сводка уходят в ближайший конец интервала, а сводка,
  перенесённая через полночь, приходит один раз следующим утром.
- Часовой пояс меняется не здесь, а в «Профиле» (см. 4.8).

#### Сообщения уведомлений

Напоминание:

```text
⏰ Через 15 минут

Оплатить интернет
Сегодня, 18:00 · Задачи

[✓ Выполнено] [😴 Отложить на час]
[📅 Завтра в 09:00] [📋 Открыть]
```

После действия сообщение редактируется:

```text
✅ Выполнено: Оплатить интернет
Следующее: сб, 5 дек, 18:00

[↩️ Отменить] [📋 Открыть список]
```

Строка «Следующее: …» появляется у повторяющейся задачи.

Любой snooze — «Отложить на час», «Завтра в 09:00» и «На час» в блоке —
отменяется, когда вхождение срока, из которого его отложили, перестало быть
текущим: срок перенесли, сняли или назначили, либо после выполнения срок
повторяющейся задачи перешёл на следующее вхождение. Смена локальной даты, в
том числе в полночь при snooze до утра, и перенос тихими часами snooze не
отменяют. Если новый срок впереди, по нему приходит обычное напоминание.

##### Напоминание о событии

```text
⏰ Через 15 минут

Маникюр
📅 Начало: Сегодня, 14:00
🏁 Конец: Сегодня, 15:30

[Закрыть] [📅 Перенести]
[📋 Открыть]
```

- Напоминание о событии приходит от начала с тем же опережением, что у задачи;
  вседневное событие напоминает в настроенное время в день начала, а каждое
  вхождение повторяющегося события получает своё напоминание.
- «Закрыть» удаляет это сообщение из чата, не меняя событие и запись
  доставки. Поэтому напоминание о том же вхождении повторно не приходит, а о
  следующем приходит по расписанию.
- «📅 Перенести» открывает тот же экран быстрого срока события, что карточка,
  без «Без срока»: меняется само событие, а напоминание о новом начале
  планируется обычным путём. Если событие уже удалено, бот сообщает «Событие
  больше недоступно» и выбор начала не открывает.
- Snooze у события нет: кнопок «✓ Выполнено», «Отложить на час» и «Завтра в
  09:00» в напоминании о событии не показывается.

Назначение:

```text

Купить торт
Сегодня, 18:00 · Покупки

[📋 Открыть] [✓ Выполнено]
```

Блок события в сводном сообщении:

```text
⏰ напоминание
Маникюр
Сегодня, 14:00 · Календарь
[📅 Перенести] [📋 Открыть]
```

Если блоков больше пяти, внизу появляется пагинация «←», «1/2», «→»;
перелистывание редактирует это же сообщение.

Правило тихих часов: уведомление, момент доставки которого попал в тихие
часы, переносится на их конец, и это время фиксируется — тики больше его не
пересчитывают, а планировщик сам по себе не ускоряет отложенное. В момент
выпуска границы проверяются ещё раз. Если накопилось два и более отложенных
уведомления видов «напоминание», «snooze» и «назначение», они приходят одним
сводным сообщением; одно — обычным. Утренняя сводка приходит отдельным
сообщением в своё зафиксированное время. В сводном сообщении пять блоков на
страницу, у каждого блока свои кнопки, внизу — общие «✓ Выполнить все» и
«Отложить все на час». Общая кнопка показывается, только если в сообщении есть
блоки задач в состоянии, к которому она применима: если в сводном только
события, общих кнопок нет.

Групповой snooze «Отложить все на час» — не то же самое, что отложенное тихими
часами: ручной выпуск и баннер его не трогают. В свой срок он собирается в
сводное вместе с отложенными тихими часами. Если его срок сам попал в тихие
часы, он становится отложенным тихими часами по общему правилу.

«✓ Выполнить все» завершает все ещё открытые задачи сводного, включая блоки,
уже отложенные «На час»: их snooze-доставка отменяется как устаревшая, и через
час по ним ничего не приходит. Блоки «Выполнено», «Задача удалена» и «Список в
архиве» не трогаются. «Отложить все на час» пропускает блоки, отложенные
«На час», пока их snooze не отменён; блок с отменённым snooze снова открыт с
обычными кнопками и попадает в групповой snooze. Блоки событий общие действия
пропускают: событие не выполняется и не откладывается, у него свои «📅
Перенести» и «📋 Открыть».

Ручной выпуск: настройки тихих часов и пояса меняются только в боте, поэтому
любая такая правка — ручной выпуск. Если после неё сейчас по новым настройкам
уже не тихо, экран настроек показывает баннер «Тихие часы выключены. Накопилось
3 уведомления — ниже» (N — фактически выпущенное число; при N = 0 баннера нет),
а сразу под ним приходит отдельное сообщение — сводное при двух и более, обычное
при одном. Для правки границ или пояса текст баннера называет новое состояние:
«Тихие часы: 22:00–09:00…» или «Часовой пояс обновлён…». Отложенная утренняя
сводка идёт отдельным сообщением после сводного и в N не входит. Если после
правки сейчас всё ещё тихо, ничего не выпускается, а отложенные переносятся на
конец нового интервала. Snooze, собственный срок которого ещё не наступил,
раньше срока не выпускается: ему возвращается собственный срок и снимается
признак отложенности тихими часами, дальше он уходит обычным порядком.

Блок показывает актуальное состояние задачи. Если задачу изменили после
выпуска, блок перерисовывается с новым названием, сроком и кнопками; действие
по устаревшей версии ничего не меняет, а сообщает «Задача уже изменилась» и
обновляет блок. Удалённая задача показывается как «Задача удалена», удалённое
событие — «Событие удалено», задача из архивного списка — «Список в архиве»;
действия по ним не выполняются. Исключение — назначение: уведомление о
назначении из архивного списка доставляется, а его блок и одиночное сообщение
показывают задачу и рабочие «✓ Выполнено»/«📋 Открыть». Устаревшая кнопка «✓
Выполнено» или «На час» на блоке события получает отказ и не создаёт
отложенное напоминание.

Если задачи уже нет, сообщение уведомления показывает «Задача больше
недоступна» с одной кнопкой «🏠 Меню». Это сообщение, а не экран, поэтому
«⬅️ Назад» в нём нет: осознанное исключение из правила навигации.

Сводка:

```text
☀️ Доброе утро!

Сегодня
☐ Оплатить интернет · 18:00
☐ Позвонить маме · 19:00

Просрочено
☐ Сдать отчёт · вчера

Покупки: 7 позиций

[📋 Задачи] [🛒 Покупки]
```

### 4.11 Ошибки и пустые состояния

| Ситуация | Текст | Действия |
| --- | --- | --- |
| Пустой список | «Пока нет задач» | «➕ Добавить», «⬅️ Назад» |
| Пустые покупки | «Список покупок пуст» | «➕ Добавить», «⬅️ Назад» |
| Нет результатов | «Ничего не нашлось» | «✏️ Изменить запрос», «⬅️ Назад» |
| LLM недоступен | «Автоматический разбор временно недоступен. Проверьте название и сохраните задачу вручную.» (или другой текст причины) — только если разбор был включён; при выключенном разборе баннера нет | Редактор с исходным текстом в названии: «💾 Сохранить», «📋 Список» и «✖ Отмена» |
| LLM ничего не нашёл | «Не нашёл в сообщении задач или покупок. Попробуйте сформулировать иначе.» | Тот же редактор с исходным текстом; повтора нет |
| Устаревшая кнопка | «Это сообщение устарело. Показываю актуальный экран.» или «Это действие устарело. Открываю актуальный экран.» | Актуальный экран |
| Нет прав | «Это доступно только владельцу.» или «Недостаточно прав для этого действия.» | Актуальный экран |
| Внутренняя ошибка | Обновление повторяется; после исчерпания попыток приходит одно нейтральное сообщение «Не получилось выполнить действие. Попробуйте ещё раз чуть позже.» | Нажатие кнопки получает пустой ответ, чтобы убрать «часики» |

Компромисс повтора: первая неудачная попытка уже отвечает на callback пустым
ответом, поэтому если повтор затем успешен, его toast Telegram не покажет —
экран при этом обновляется.

## 5. Callback-токены

- Генерируются при рендере каждой кнопки.
- Формат `t:<16 base64url>`; в БД — SHA-256 хеш.
- Привязка: `household_id`, `telegram_user_id`, `action`, `payload`, `version`.
- TTL ≤24 часа; одноразовые; потребление атомарное.
- При нажатии:
  1. `answerCallbackQuery` (быстрый ответ, чтобы убрать «часики»);
  2. проверка пользователя;
  3. выполнение действия;
  4. редактирование сообщения.
- Просроченный/повторный токен → toast + обновление экрана.
- Чужой токен → отказ без раскрытия данных.

## 6. Редактирование сообщений

- Один поток навигации — одно активное сообщение (`telegram_views.message_id`).
- Экран редактирует активное сообщение, только когда оно видно пользователю:
  нажата кнопка на нём самом или оно последнее в чате. Иначе экран приходит
  новым сообщением внизу чата, а прежнее активное сообщение удаляется.
- Активное сообщение засыпано, если после него в чате появилось другое
  сообщение бота или осталось сообщение пользователя. Признак
  `telegram_views.buried` ставят:
  - outbox — после успешной доставки строки `message` (уведомление, сводка,
    `/help`, `say`);
  - outbox — когда не удалось удалить сообщение пользователя по причине,
    отличной от «сообщения нет», в том числе когда удаление ушло в
    dead-letter;
  - outbox — когда запасной путь правки (`replace_or_send`) отправил экран
    новым сообщением;
  - воркер обновлений — когда текст отброшен из-за переполнения очереди
    отложенных.
  Outbox сбрасывает `buried = false`, когда отправляет экран новым сообщением
  и записывает его `message_id` в `telegram_views`. Правка на месте
  (`edit`, в том числе правка уведомления) признак не меняет: сообщение уже
  было в чате.
- Режим доставки экрана — поле `placement` в строке `screen`:

  | `placement` | Источник | Поведение при доставке |
  | --- | --- | --- |
  | `in_place` | нажатие кнопки на самом якоре: `message_id` кнопки совпадает с `telegram_views.message_id` | всегда правка |
  | `visible` | текст, ответ поля редактора, кнопка уведомления, фоновые задания, остальные пути; значение по умолчанию | правка при `buried = false`, иначе новый экран внизу и удаление старого |
  | `fresh` | `/start` (включая онбординг и `/start <code>`), `/menu` | всегда новый экран внизу и удаление старого |

- Кнопка устаревшего сообщения (её `message_id` не совпадает с активным
  якорем) действие не выполняет: показывается всплывающая подсказка, а
  актуальный экран перерисовывается. Кнопки уведомлений всегда открывают
  экран как `visible`, даже если нажаты на сообщении, которое выглядит как
  якорь.
- `/start` и `/menu` — способ вернуть окно, если пользователь удалил активное
  сообщение только у себя: Telegram не сообщает боту об этом, а правка такого
  сообщения может быть принята как успешная. Обе команды всегда присылают
  экран заново.
- Если правка невозможна (сообщение удалено, старше лимита, нет прав) —
  удалить старое и отправить новое ровно один раз. Ошибка удаления старого
  сообщения не отменяет новый экран.
- Старый якорь старше 48 часов Telegram удалить не даёт: новый экран всё
  равно приходит, а кнопки прежнего сообщения обрабатываются как устаревшие.
- `telegram_views` хранит `message_id`, `buried` и `view_key`, чтобы после
  перезапуска продолжить редактирование.
- Входящие текстовые сообщения (текст на разбор, ответы полей редактора,
  команды) удаляются из приватного чата после успешной обработки; нетекстовые
  сообщения не удаляются. Если сообщение пользователя осталось в чате
  (удаление не удалось или текст отброшен лимитом), экран считается
  засыпанным, и следующий экран приходит новым сообщением внизу.

## 7. Текстовый ввод и состояния

- Активная форма хранится в `conversation_states`. Правку и создание элемента
  ведёт состояние `Editor` (`target`, `draft`, `touched`, `field`); оно заменило
  прежние формы создания и правки. Кроме редактора, там живут формы ввода
  текста: `DueText` (дата и время быстрого срока), `Search` (поиск), `Rename`
  (имя), `Lead` и `Time` (время уведомлений), `DeleteHousehold` и `Onboarding`
  — полный список в `Form` (`model.rs`).
- Ответ на поле редактора удаляется из чата после обработки, а принятое
  значение остаётся видно в редакторе.
- Если у редактора открыто поле, которое ждёт текст, ответ становится его
  значением. Если открыт сам редактор между полями или поле выбирается
  кнопками, текст не уходит в разбор: бот показывает баннер «Сначала сохраните
  или отмените правку.».
- Если формы нет, путь текста выбирается по активному экрану:

  | Экран | Куда уходит текст |
  | --- | --- |
  | главное меню | общий разбор |
  | редактор, поле ждёт текст | значение поля |
  | редактор, поле не ждёт текст | баннер «Сначала сохраните или отмените правку.» |
  | поиск и результаты поиска | новый поиск |
  | список покупок | прямое добавление в этот список |
  | список задач | разбор с этим списком как списком по умолчанию (`default_list_id`) |
  | чек-лист и остальные экраны | общий разбор |

  Без разбора (`LLM_CAPTURE_ENABLED=false`) общий разбор и список задач
  открывают редактор с исходным текстом и выбором списка; список покупок
  делит текст по запятым и переводам строк. Целевой список чек-листа разбору не
  передаётся: пункты чек-листа могут попасть в черновик; без разбора текст на
  чек-листе открывает редактор в списке задач по умолчанию.
- Подсказка ввода строится по той же таблице, что и путь текста. Поэтому
  экран не обещает другого: в меню — «Напишите задачу или покупку — я разберу.»
  (без разбора — «Напишите название задачи — открою редактор задачи.»), в
  поиске — «Напишите запрос», в списке — «Напишите — добавлю в «<список>»»
  (без разбора на покупках — с уточнением «через запятую или с новой строки»).
  На чек-листе подсказка та же, что в меню, и не называет список: текст уходит
  в общий разбор без целевого списка.
- Прямое добавление покупок. Позиции сохраняются сразу, без «Сохранить всё».
  Пока идёт разбор, экран списка остаётся на месте с баннером «Добавляю…».
  Дубликат не сохраняется: баннер предлагает «➕ Увеличить до …» или
  «📄 Добавить отдельно». «↩️ Отменить» удаляет созданные позиции в течение
  10 минут; она не уводит с чужого экрана и сохраняет «Открыть» ожидающего
  черновика того же добавления, в том числе после выбора по дубликату.
  Подробности — в 4.6.
- Поздний результат. Готовый результат обычного разбора открывается экраном
  черновика, только если активен статус этого разбора или карточка этого же
  черновика. Иначе текущий экран не заменяется: на нём появляется баннер
  «Черновик готов» с кнопкой «Открыть». Незавершённый редактор тоже остаётся
  открытым. Результат прямого добавления, если пользователь ушёл со списка,
  приходит баннером «Добавлено в «Покупки»: …». Если у этого результата есть
  элементы для черновика (другой тип или невалидная покупка), действует то же
  правило: на списке покупок остаётся список с баннером «Добавлено: …
  Черновик готов» и кнопками «↩️ Отменить» и «Открыть», на чужом экране —
  баннер «Добавлено в «Покупки»: …» и «Открыть», а карточка заменяет экран
  только когда активного экрана нет, активен статус этого задания или карточка
  этого же черновика.
- Поздняя ошибка разбора. Окончательная ошибка не заменяет чужой экран:
  на нём появляется баннер с кнопкой «✍️ Ввести вручную». Кнопка одноразовая и
  несёт исходный текст, нажатие открывает ручной редактор с этим текстом в
  названии. На статусе этого же разбора и без активного экрана редактор
  открывается сразу; остальные ошибки разбора ведут себя так же. У
  direct-задания на списке покупок кнопка открывает общий ручной редактор:
  отдельного редактора покупки в деградации direct-задания нет.
- Дописывание в черновик. Если у чата есть ожидающий черновик Telegram, новый
  разбор дописывается в него, пока элементов вместе не больше 20, а исходный
  текст всех сообщений — не больше 2000 символов. Дописывание продлевает
  черновик до 15 минут от последнего сообщения. Если пределы не позволяют,
  создаётся новый черновик, а прежний остаётся ожидающим. В карточке каждое
  сообщение показывается отдельной цитатой в порядке отправки.
- Возврат к черновику. Пока черновик ожидает, главное меню показывает строку
  «📝 Ждёт подтверждения: N пунктов» с кнопкой «Открыть» (4.2).
- Прежнее состояние форм создания и правки (`{"form":"create", …}`,
  `{"form":"edit", …}`) не разбирается как редактор и считается истёкшим: бот
  сообщает, что правка устарела, и предлагает начать заново.
- Отказы на текст (слишком длинное сообщение, частота разборов, неизвестная
  команда) показываются баннером на текущем экране; отдельного сообщения об
  ошибке нет.
- `/help` приходит отдельным сообщением. `/start` и `/menu` возвращают окно
  внизу чата, если активный экран засыпан или удалён у пользователя.
- Команды:
  - `/start` — меню, онбординг или экран первого контакта по состоянию
    инсталляции (см. 4.1);
  - `/start <code>` — приглашение;
  - `/menu` — главное меню;
  - `/help` — краткая справка;
  - `/cancel` — отменить текущую форму;
  - `/settings` — настройки.
- Одна активная форма на чат; TTL 15 минут.
- При вводе неверного значения — пояснение и повторный запрос, введённые данные
  сохраняются.
- `/cancel` закрывает форму сразу, с баннером «Действие отменено.»; отдельного
  подтверждения нет.

## 8. Пагинация

- 8 элементов на страницу (задачи, покупки, поиск, интеграции).
- Кнопки «←»/«→», номер страницы, «В начало».
- Сортировка списка стабильна: секция срока → срок → приоритет →
  `created_at` → `id`; поиск — релевантность → срок → `id`.
- После действия текущая страница перерисовывается; если элементов не осталось —
  предыдущая.
- Курсор поиска для API — base64url от `(rank, due, id)`; в боте — номер
  страницы.

## 9. Лимиты

| Операция | Лимит |
| --- | --- |
| Обновления от пользователя | 20/мин. |
| LLM-разборы | 10/мин, 200/сутки на household. |
| Приглашения | 5/час на household. |
| Исходящие в чат | 1/сек. |
| Исходящие глобально | 30/сек. |
| Элементов в списке | 8 на страницу. |

Обновление сверх лимита не отклоняется: оно остаётся `pending` и выполняется,
когда освобождается слот лимитера, в исходном порядке (`available_at`,
`update_id`). Сообщения в чат о лимите нет. Нажатие кнопки сразу получает пустой
ответ, чтобы убрать «часики»; результат действия появляется после освобождения
слота.

Предел очереди относится только к новым обновлениям: уже отложенное обновление
при повторном отказе лимитера откладывается снова, поэтому порядок не
нарушается. Строки, ожидающие повтора после сбоя, место в пределе не занимают.
У пользователя не больше 20 отложенных лимитером обновлений. Следующее сверх
этого отбрасывается без выполнения: нажатие кнопки получает пустой ответ, чтобы
убрать «часики», а сообщение с отброшенным текстом остаётся в чате, и следующий
экран приходит новым сообщением ниже. Воркер учитывает откладывания и
отбрасывания в `telegram_updates_total{status}` как `deferred` и `dropped`;
остальные исходы — `processed`, `failed` и `dead`. Webhook при этом возвращает
`200`, иначе Telegram будет повторять доставку (`429` получают только API и
лимит по IP). Действия сверх лимита не теряются: они выполняются после
освобождения слота; отбрасывается только то, что не поместилось в очередь
отложенных.

## 10. Локализация и форматирование

- Русский язык MVP.
- Даты: «сегодня», «завтра», «послезавтра», «пн, 3 ноя», «3 ноя 2026, 18:00».
- Время — в timezone пользователя.
- Склонения: «1 задача», «2 задачи», «5 задач»; «1 покупка», «2 покупки»,
  «5 покупок».
- Числа: десятичная запятая в UI, точка в API.
- Ошибки — без английских служебных строк.
- Эмодзи — вспомогательные; текст должен быть понятен без них.

## 11. Доступность

- Все действия доступны через текст и кнопки.
- Статус передаётся текстом («выполнено», «просрочено»), а не только цветом.
- Подпись смены статуса называет действие: «✓ Выполнено» у задачи, «✓ Куплено»
  у покупки, «Применить» в мультивыборе. Кнопок с подписью «Готово» нет.
- Кнопки имеют глагольные подписи: «Добавить», «Сохранить», «Отменить».
- Длинные списки разбиваются на страницы; нет горизонтального скролла.
- Экран не зависит от размера шрифта: текст переносится, кнопки не обрезаются.
- Для скринридеров — осмысленный порядок элементов и короткие заголовки.

## 14. Реализация: допущения и ограничения

- **Схема RichMessage сверена с Bot API (2026-10-31).** Адаптер `HttpTelegramApi`
  вызывает `sendRichMessage` (`{chat_id, rich_message: {html}}`) и
  `editMessageText` (`{chat_id, message_id, rich_message: {html}}`); отдельного
  метода `editRichMessage` в Bot API нет. Ответ — объект с `message_id`.
  В `InputRichMessage` заполняется ровно одно поле (`html`). Кнопки размечаются
  как `<tg-button type="callback_data" data="…">`, ряды — `<tg-button-row>`
  (атрибут `align` необязателен). Менять схему нужно только в
  `src/telegram/api.rs`, контракт зафиксирован в `tests/telegram_api.rs`.
  Обычные сообщения (уведомления об изменении состава) идут через `sendMessage`.
- **Цитаты в RichMessage проверены на живом боте (2026-11-02).** Тестовый бот
  `@tasklerqtestbot`, Telegram Desktop и Android. `sendRichMessage` и
  `editMessageText` с `rich_message` принимают `<blockquote>` и
  `<blockquote expandable>`; Bot API возвращает блоки `blockquote` и
  `expandable_blockquote`. Короткая цитата отображается полосой, длинная —
  свёрнутой и раскрывается по нажатию. Запасной блок `Details` для длинного
  текста не нужен; проверены и отправка нового сообщения, и правка
  существующего.
- **Раскладка и лимиты RichMessage проверены на живом боте (2026-11-06,
  этап 0 change 0004).** Тестовый бот `@tasklerqtestbot`, Telegram Desktop
  (узкое окно ~430 px). Все пробы ниже приняты и `sendRichMessage`, и
  `editMessageText`.
  - *Ширина кнопок.* Без `align` кнопки ряда делят ширину поровну: в
    `[☐][Оплатить интернет · 18:00]` и `[☐ Молоко · 2 л][⋯]` чекбокс и «⋯»
    занимают половину строки.
  - *Атрибут `align`* (`left`, `center`, `right`) делает каждую кнопку по
    ширине текста и прижимает ряд к краю. Слишком длинная подпись обрезается
    многоточием, перенос строки не делается.
  - *Кнопки вида «📅 Срок» в ряд.* Без `align` по 2 и по 3 подписи
    («👤 Исполнитель», «🔁 Повторение») видны целиком, по 4 обрезаются
    («Приори…»); карточка `[✓ Выполнено][📅 Срок][✏️ Править][🗑 Удалить]`
    обрезает «Выполне…», а 2+2 помещается. С `align=left` четыре поля и
    карточка из четырёх помещаются, восемь — обрезаются до значков.
  - *Кнопки внутри абзаца* (`<tg-button>` в `<p>` или `<li>`) рисуются
    компактными «чипсами» по ширине текста и переносятся на следующую строку:
    восемь полей редактора занимают две строки без обрезки.
  - *`style`.* `success`, `danger`, `primary` окрашивают кнопку; `link` в
    абзаце — синяя ссылка, в ряду выглядит обычной кнопкой. `type="disabled"`
    рисуется тусклой.
  - *Таблицы* в 3 и 4 колонки читаются без горизонтальной прокрутки, в ячейках
    текст переносится; `bordered striped compact` добавляет рамки.
  - *`ul/li`, `<input type="checkbox">` и `<hr>`* при правке сообщения
    отображаются; чекбоксы — значками, не кнопками.
  - *`sendRichMessageDraft`* принимает `<tg-thinking>` и возвращает `true`,
    но клиент черновик не показал: четыре шага по 6 секунд с одним
    `draft_id` в чате не появились, пришло только итоговое сообщение
    `sendRichMessage`. Для «Разбираю…» на этот метод полагаться нельзя.
  - *Лимиты.* В ряду до 8 кнопок (9 — `RICH_MESSAGE_BUTTONS_TOO_MANY`). До 500
    блоков, ряды кнопок тоже блоки (501 — `RICH_MESSAGE_BLOCKS_TOO_MANY`);
    400 кнопок в одном сообщении проходят. Латинский текст длиннее 32 768
    символов отклоняется (`RICH_MESSAGE_TEXT_TOO_LONG`), а **кириллический не
    отклоняется, а молча обрезается** примерно до 17 490 символов на
    сообщение: хвостовые блоки пропадают, ответ `ok`. Разметка в лимит не
    входит (HTML 45 000 символов при тексте 10 000 проходит). Рендереру нужен
    свой бюджет текста; на ошибку API полагаться нельзя.
  - *Android* показывает то же, что Desktop, с двумя отличиями: таблица в 3–4
    колонки прокручивается по горизонтали, а в ряду из 4 кнопок длинные
    подписи слегка обрезаны в конце.
  - *iOS* не проверен: клиента не было под рукой.
  - **Вывод для раскладки.** Поля редактора — ряды по 3 без `align` (на
    Desktop и Android подписи целиком, кнопки крупные). Действия карточки — по
    2 в ряд (2+2), не по 4. Ряд навигации «⬅️ Назад · 🏠 Меню» — по 2 без
    `align`. `MAX_BUTTONS_PER_ROW = 3` остаётся. Таблицы не использовать для
    журнала и списков: на Android они прокручиваются по горизонтали, а записи
    должны открываться тапом. `align` и кнопки внутри абзаца не используются
    в 0004: короткие «чипсы» мельче и плотнее обычных кнопок, а длинная
    подпись с `align` обрезается.
- **Имя бота** для ссылок-приглашений задаёт `TELEGRAM_BOT_USERNAME`
  (по умолчанию `tasklerqbot`).
- **Группы** игнорируются без сохранения и без пояснения в чате: бот не хранит
  идентификаторы групп, поэтому «одно пояснение» отправить некому.
- **Фильтры списка и сортировка** (раздел 4.3) и фильтры поиска по списку,
  исполнителю и тегу (раздел 4.7) не реализованы: поиск идёт по тексту со
  статусом «открытые / выполненные / все», до 50 результатов.
- **Правило повторения** задаётся в боте без даты окончания (`until`):
  периодичность, дни недели, правило месяца и интервал.
- **Настройки уведомлений** в боте: напоминания, сводка, назначения, тихие часы
  (вкл/выкл), lead time, время сводки, время вседневного напоминания, начало и
  конец тихих часов. Изменения применяются со следующего тика планировщика и
  только к своему пользователю. Отложенные тихими часами уведомления не
  теряются: напоминание и сводка уходят в ближайший конец интервала, а сводка,
  перенесённая через полночь, приходит один раз следующим утром.
- **Уведомления** (напоминание, назначение, сводка, результат действия)
  собираются в `telegram::bot::notify`; ставит их в очередь планировщик
  (фаза 7). Кнопки уведомлений отдельные от экрана навигации и редактируют своё
  сообщение.
- **Журнал** показывает до 100 последних событий членства за 90 дней; коды
  приглашений и токены в события не попадают, а ссылка-приглашение видна только
  в момент создания.
- **Известные ограничения этапа C: прямое добавление и дописывание.**
  - В прямом добавлении существующие позиции списка читаются без блокировки
    строк списка: два одновременно завершившихся задания на один список могут
    оба пройти проверку дубликата.
  - Если разбор direct-задания вернул больше 20 элементов, текст не делится по
    запятым и переводам строк: бот сообщает, что элементов больше 20, и
    пользователь разделяет текст сам. Такое же ограничение у деления без LLM:
    больше 20 позиций не создаётся.
  - Строка «📝 Ждёт подтверждения» показывается и у ожидающего черновика, в
    котором не осталось пунктов («0 пунктов»); спека этот случай не
    оговаривает.

## 15. Ручной чек-лист клиентов

Перед релизом пройти на Telegram iOS, Android и Desktop:

- [ ] `/start` создаёт пространство; кнопки часового пояса видны целиком.
- [ ] Второй пользователь без приглашения при существующем household видит
      «Это частное пространство» и предложение попросить приглашение, а не
      форму онбординга.
- [ ] Кнопки в ряду по 3 не обрезают подписи на узком экране.
- [ ] Владелец выпускает токен в **Настройки → 🔌 Интеграции**; сообщение с
      токеном приходит под спойлером со строкой «Сообщение удалится через час».
- [ ] «Я сохранил» удаляет сообщение с токеном сразу, а без нажатия кнопки оно
      удаляется через час.
- [ ] Переход «меню → список → карточка → назад» не создаёт новых сообщений.
- [ ] После удаления сообщения бота нажатие кнопки возвращает свежий экран
      одним новым сообщением.
- [ ] Длинная цитата с описанием задачи сворачивается и разворачивается.
- [ ] Эмодзи в подписях отображаются; статус понятен и без них.
- [ ] Название с символами `<`, `>`, `&` показывается буквально.
- [ ] Даты: «сегодня», «завтра», «вт, 3 ноя», «3 ноя 2026, 18:00».
- [ ] Склонения: «1 задача», «2 задачи», «5 задач», «21 задача».
- [ ] Пустые списки показывают пояснение и кнопку «Добавить».
- [ ] Ссылка-приглашение открывается и подставляет код в `/start`.
- [ ] Повторное нажатие кнопки и кнопка устаревшего сообщения показывают
      всплывающую подсказку и не дублируют действие.
- [ ] Длинный список (больше 8 элементов) листается кнопками «←» и «→».
- [ ] «📜 История» на списке задач открывает журнал выполнений всего
      household: группы по плановому дню, «(впереди)» у будущих дней, «Без
      срока» в конце; запись открывает карточку, «Назад» возвращает на ту же
      страницу.
- [ ] В карточке задачи с выполнениями свёрнутая цитата «Выполнения»
      раскрывается, а кнопки записей журнала не обрезаются.
- [ ] «↩️ Вернуть» из журнала и раздела «Выполнено сегодня» возвращает
      последнее выполнение; после возврата запись исчезает из обоих списков.
