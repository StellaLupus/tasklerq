# Spec Delta

## ADDED Requirements

### Requirement: Подключение Telegram в консоли

Консоль SHALL принимать токен бота, проверять его вызовом `getMe` и
сохранять имя и id бота. Для режима webhook консоль MUST запрашивать публичный
HTTPS-адрес, сама генерировать секрет не короче 32 байт, вызывать `setWebhook`
и показывать результат `getWebhookInfo`. Шаг мастера MUST допускать пропуск.
Если `TELEGRAM_BOT_TOKEN` задан окружением, раздел MUST быть только для чтения.

#### Scenario: Неверный токен

- **WHEN** администратор вводит токен, на который `getMe` отвечает ошибкой
- **THEN** консоль сообщает, что токен не принят Telegram
- **AND** токен не сохраняется, действующий бот не меняется

#### Scenario: Успешное подключение

- **WHEN** администратор вводит верный токен и публичный адрес
  `https://tasklerq.example.com`
- **THEN** консоль показывает имя бота из `getMe`
- **AND** webhook зарегистрирован на `https://tasklerq.example.com/webhooks/telegram`
  с сгенерированным секретом
- **AND** страница показывает адрес, число ожидающих обновлений и последнюю
  ошибку из `getWebhookInfo`

#### Scenario: Публичный адрес без HTTPS

- **WHEN** в production администратор вводит адрес `http://tasklerq.example.com`
- **THEN** консоль отклоняет сохранение и называет требование HTTPS

#### Scenario: Telegram из окружения

- **WHEN** `TELEGRAM_BOT_TOKEN` задан в окружении
- **THEN** страница Telegram показывает имя бота и состояние webhook
- **AND** поля нельзя изменить

### Requirement: Применение настроек Telegram без перезапуска

Сохранение токена, режима или адреса в консоли SHALL применяться без
перезапуска процесса: прежние Telegram-воркеры MUST остановиться, дождавшись
завершения начатой отправки, новые — запуститься с новыми настройками. Задания
в очередях MUST NOT теряться. Пока идёт переключение, webhook MUST отвечать так,
чтобы Telegram повторил доставку.

#### Scenario: Бот подключён без перезапуска

- **WHEN** сервис работал без Telegram, а администратор подключил бота в консоли
- **THEN** бот отвечает на `/start` без перезапуска процесса
- **AND** напоминания начинают доставляться

#### Scenario: Сообщения в очереди при переключении

- **WHEN** в исходящей очереди есть сообщения, а администратор перевыпускает
  секрет webhook
- **THEN** после переключения сообщения доставляются
- **AND** ни одно не доставлено дважды

#### Scenario: Отключение бота

- **WHEN** администратор выключает Telegram в консоли
- **THEN** воркеры Telegram останавливаются
- **AND** `/webhooks/telegram` отвечает так же, как при `TELEGRAM_MODE=disabled`
- **AND** HTTP API и capture продолжают работать

### Requirement: Смена бота

Если `getMe` нового токена возвращает id, отличный от сохранённого, а в
household есть участники, консоль SHALL требовать явного подтверждения и
предупреждать, что новый бот не сможет писать участникам, пока они не отправят
ему `/start`. После смены система MUST вызвать `deleteWebhook` для прежнего
токена; ошибка этого вызова MUST NOT отменять смену.

#### Scenario: Смена бота без подтверждения

- **WHEN** администратор вводит токен другого бота при трёх участниках и не
  подтверждает смену
- **THEN** действующий бот не меняется

#### Scenario: Смена бота с подтверждением

- **WHEN** администратор подтверждает смену бота
- **THEN** новый бот начинает принимать обновления
- **AND** прежнему боту отправлен `deleteWebhook`

### Requirement: Ссылка-claim владельца

Консоль SHALL выпускать одноразовую ссылку `https://t.me/<бот>?start=own_<код>`
и её QR-код для household без владельца, а в режиме `single` — и для пустой
инсталляции. Код MUST содержать не менее 128 бит случайности, MUST действовать
24 часа и MUST храниться хешем. Первый пользователь, открывший ссылку, MUST
стать владельцем этого household (или пройти онбординг); выпуск новой ссылки
для того же household MUST гасить прежнюю.

#### Scenario: Владелец по ссылке

- **WHEN** пользователь с Telegram ID `111` открывает действующую ссылку-claim
  household без владельца
- **THEN** он становится владельцем этого household и видит главное меню
- **AND** событие назначения владельца записано в аудит

#### Scenario: Ссылка уже использована

- **WHEN** второй пользователь открывает ту же ссылку
- **THEN** бот показывает тот же экран, что и для `/start` без ссылки
- **AND** владелец не меняется

#### Scenario: Владелец уже есть

- **WHEN** у household появился владелец
- **THEN** консоль не предлагает выпустить ссылку-claim для него

#### Scenario: Ссылки для разных household

- **WHEN** в режиме `multi` выпущена ссылка для household «Дача», а затем для
  household «Квартира»
- **THEN** обе ссылки действуют

### Requirement: Привязка Telegram к администратору

Консоль SHALL выпускать ссылку `https://t.me/<бот>?start=adm_<код>` (15 минут,
одноразовая). Открывший её аккаунт MUST становиться кандидатом, а привязка MUST
вступать в силу только после подтверждения в консоли с показом имени аккаунта.
Привязан может быть один аккаунт; привязка MUST NOT делать его участником
household. Консоль MUST позволять отвязать аккаунт.

#### Scenario: Привязка

- **WHEN** администратор открывает ссылку привязки в своём Telegram и
  подтверждает показанный аккаунт в консоли
- **THEN** бот сообщает, что аккаунт привязан
- **AND** консоль показывает имя привязанного аккаунта

#### Scenario: Ссылку открыл посторонний

- **WHEN** ссылку привязки открыл чужой аккаунт, а администратор отклонил его в
  консоли
- **THEN** аккаунт не привязан
- **AND** команда `/admin` для него обрабатывается как неизвестная

#### Scenario: Привязка не даёт членства

- **WHEN** аккаунт, не состоящий в household, привязан к администратору
- **THEN** главное меню бота ему по-прежнему недоступно

### Requirement: Восстановление доступа через бота

Команда `/admin` от привязанного аккаунта SHALL присылать одноразовую ссылку
восстановления на адрес консоли (15 минут) без предпросмотра ссылки. Сообщение
MUST удаляться через 15 минут. От непривязанного аккаунта команда MUST
обрабатываться как неизвестная. Запросы MUST ограничиваться тремя в час.

#### Scenario: Восстановление привязанным аккаунтом

- **WHEN** привязанный аккаунт отправляет `/admin`
- **THEN** бот присылает ссылку на страницу восстановления консоли
- **AND** через 15 минут сообщение со ссылкой удаляется
- **AND** выпуск ссылки записан в аудит

#### Scenario: Чужой аккаунт

- **WHEN** непривязанный аккаунт отправляет `/admin`
- **THEN** бот отвечает так же, как на неизвестную команду
- **AND** ссылка не выпускается

#### Scenario: Адрес консоли неизвестен

- **WHEN** привязанный аккаунт отправляет `/admin`, а консоль ещё ни разу не
  открывалась после обновления
- **THEN** бот сообщает, что адрес консоли неизвестен, и предлагает
  `tasklerq admin reset-password`
