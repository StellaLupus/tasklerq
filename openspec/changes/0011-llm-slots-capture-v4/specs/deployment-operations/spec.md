# Spec Delta

## MODIFIED Requirements

### Requirement: Конфигурация через окружение

Система SHALL читать конфигурацию из переменных окружения и MUST завершать
запуск с понятной ошибкой, если отсутствует обязательный параметр или он
невалиден. Обязательные параметры MUST включать `DATABASE_URL` и
`PUBLIC_BASE_URL`; при `TELEGRAM_MODE=webhook` — `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_WEBHOOK_SECRET`; при включённом LLM — адрес и модель основного слота
(`LLM_PRIMARY_URL`, `LLM_PRIMARY_MODEL`). Резервный слот MUST считаться
настроенным, только если заданы и его адрес, и его модель; заданный наполовину
MUST приводить к ошибке запуска. Переменные `HA_BASE_URL`, `HA_TOKEN` и
`HA_AI_TASK_ENTITY_ID` больше не читаются; если они заданы, сервис MUST
запуститься и MUST записать предупреждение без их значений.

#### Scenario: Отсутствует DATABASE_URL

- **WHEN** сервис запускается без `DATABASE_URL`
- **THEN** процесс завершается с кодом ошибки
- **AND** сообщение указывает отсутствующий параметр
- **AND** секреты не выводятся

#### Scenario: Невалидный URL

- **WHEN** `PUBLIC_BASE_URL` не является HTTPS-URL в production
- **THEN** сервис отказывается запускаться
- **AND** сообщает ожидаемый формат

#### Scenario: LLM включён без основного слота

- **WHEN** `LLM_CAPTURE_ENABLED=true`, а `LLM_PRIMARY_URL` не задан
- **THEN** процесс завершается с кодом ошибки
- **AND** сообщение называет отсутствующий параметр

#### Scenario: Резервный слот задан наполовину

- **WHEN** задан `LLM_FALLBACK_URL`, а `LLM_FALLBACK_MODEL` пуст
- **THEN** сервис отказывается запускаться и называет недостающий параметр

#### Scenario: Остались переменные Home Assistant

- **WHEN** в окружении заданы `HA_TOKEN` и корректные параметры основного слота
- **THEN** сервис запускается
- **AND** лог содержит предупреждение, что `HA_TOKEN` не используется, без его
  значения

### Requirement: Health и наблюдаемость

Система SHALL предоставлять `/health/live` для проверки процесса и
`/health/ready` для проверки базы, применённых миграций и допустимой задержки
очередей. Если в режиме `single` активных household больше одного,
`/health/ready` MUST оставаться успешным и MUST содержать предупреждение о
деградации без названий и идентификаторов household. При включённом LLM
`/health/ready` MUST оставаться успешным независимо от состояния слотов и MUST
содержать предупреждение, если предохранители всех настроенных слотов
разомкнуты или если какой-либо слот не имеет статуса проверки «прошёл».

#### Scenario: Успешная readiness

- **WHEN** база доступна, миграции применены, очередь не переполнена
- **THEN** `/health/ready` возвращает `200`
- **AND** содержит версию и время проверки

#### Scenario: Переполненная очередь

- **WHEN** задержка очереди превышает настроенный порог
- **THEN** `/health/ready` возвращает ошибку
- **AND** метрика задержки отражает значение

#### Scenario: Readiness в деградированном режиме

- **WHEN** в режиме `single` в базе два активных household, а остальные
  проверки пройдены
- **THEN** `/health/ready` возвращает `200`
- **AND** ответ содержит предупреждение `multiple_households`

#### Scenario: Все слоты LLM недоступны

- **WHEN** предохранители основного и резервного слотов разомкнуты, а
  остальные проверки пройдены
- **THEN** `/health/ready` возвращает `200`
- **AND** ответ содержит предупреждение `llm_unavailable`

#### Scenario: Слот не проверен

- **WHEN** основной слот не проходил проверку smoke-набором
- **THEN** `/health/ready` возвращает `200`
- **AND** ответ содержит предупреждение `llm_slot_unverified` с именем слота
