# Spec Delta

## MODIFIED Requirements

### Requirement: Причины провала и оценка задержки

Отчёт проверки MUST указывать для каждой непройденной фразы причину:
`timeout`, `transport` с кодом, `schema` с кодом ошибки разбора, `validation`
с полем или `mismatch` с перечнем расхождений «ожидали — получили» по полям.
Названия MUST сравниваться по основам слов, без учёта регистра и порядка слов;
в строгом режиме это единственное правило сравнения.
Отчёт MUST содержать оценку задержки по 95-му перцентилю: до 2 с —
«замечательно», до 4 с — «хорошо», до 6 с — «приемлемо», до 10 с — «медленно»,
больше — «неприемлемо».

Проверка MUST поддерживать второй, нормализованный режим сравнения названий
элементов: кроме основ слов он сближает инфинитивные видовые пары глаголов и
синонимы («Вынести мусор» и «Выносить мусор» — одно название). Нормализованный
режим MUST NOT применяться к именам списков: имя списка — идентификатор из
контекста household, оно сравнивается строго. Действующий режим MUST храниться
как стандарт слота в настройках; отсутствие настройки MUST означать `strict`.
Смена стандарта MUST выполняться только явным выбором оператора при запуске
проверки и MUST сохраняться за слотом. Оба режима MUST считаться по одному
прогону слота, без повторных вызовов, и отчёт MUST показывать пройденное число
для каждого режима. Вердикт, код возврата и сохраняемый результат MUST
считаться по стандарту прогона.

#### Scenario: Расхождение по полю

- **WHEN** эталон ожидает событие на `2026-11-12`, а слот вернул задачу на ту
  же дату
- **THEN** фраза не пройдена с причиной `mismatch`
- **AND** отчёт показывает: тип — ожидали `events`, получили `tasks`

#### Scenario: Название в другой форме

- **WHEN** эталон ожидает название «Оплатить интернет», а слот вернул
  «оплата интернета»
- **THEN** названия считаются совпавшими

#### Scenario: Вид глагола в названии

- **WHEN** эталон ожидает «Вынести мусор», слот вернул «Выносить мусор», а
  стандарт слота — `strict`
- **THEN** фраза не пройдена с причиной `mismatch`
- **AND** в отчёте для нормализованного режима она пройдена

#### Scenario: Префиксный вид глагола

- **WHEN** эталон ожидает «Заплатить за квартиру», слот вернул «Платить за
  квартиру», а стандарт слота — `normalized`
- **THEN** названия считаются совпавшими
- **AND** при стандарте `strict` фраза не пройдена с причиной `mismatch`

#### Scenario: Имя списка при нормализованном режиме

- **WHEN** в контексте household есть списки «Картошка» и «Картофель»
- **AND** эталон ожидает список «Картошка», а слот вернул «Картофель»
- **AND** стандарт слота — `normalized`
- **THEN** фраза не пройдена с причиной `mismatch`
- **AND** расхождение указано по полю «список»

#### Scenario: Выбран нормализованный стандарт

- **WHEN** проверка запущена с `--titles normalized`
- **THEN** слот вызывается по одному разу на фразу
- **AND** отчёт печатает пройденное число и для `strict`, и для `normalized`
- **AND** код возврата и сохраняемый вердикт считаются по `normalized`
- **AND** стандарт `normalized` сохранён за слотом
- **AND** следующий прогон без флага судит по `normalized`

### Requirement: Отпечаток и статус проверки слота

Результат проверки MUST сохраняться с отпечатком слота: вид слота, модель, хост
адреса, хеш контракта (промпт и схема), хеш smoke-набора, таймаут слота и
стандарт сравнения названий; токен и квота в отпечаток не входят. Сохранённая
проверка MUST помнить свой стандарт, и он MUST читаться из сохранённых частей
отпечатка. Действующий стандарт слота MUST храниться в настройках слота. Статус
слота MUST быть одним из: «не проверен», «устарел» (отпечаток действующей
конфигурации и стандарта отличается от сохранённого), «прошёл» и «не прошёл» с
числом пройденных фраз. Статус MUST считаться по действующему стандарту слота и
MUST называть стандарт сохранённой проверки. Смена стандарта MUST делать
сохранённую проверку устаревшей.

#### Scenario: Смена модели

- **WHEN** слот прошёл проверку, а затем в его настройках изменили модель
- **THEN** статус слота становится «устарел»

#### Scenario: Смена токена

- **WHEN** слот прошёл проверку, а затем изменили только его токен
- **THEN** статус слота остаётся «прошёл»

#### Scenario: Изменён промпт

- **WHEN** слот прошёл проверку, а затем вышла новая версия контракта
- **THEN** статус слота становится «устарел»

#### Scenario: Смена стандарта сравнения

- **WHEN** слот прошёл строгую проверку, а затем стандарт слота изменили на
  `normalized`
- **THEN** статус слота становится «устарел»
- **AND** отчёт и лог называют стандарт сохранённой проверки — `strict`

#### Scenario: Нормализованный стандарт как действующий

- **WHEN** слот проверен и пройден при стандарте `normalized`
- **THEN** статус слота — «прошёл»
- **AND** строка лога старта называет `normalized`
- **AND** сохранённая проверка и отчёт указывают `normalized`
