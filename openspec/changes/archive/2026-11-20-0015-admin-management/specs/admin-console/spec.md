# Spec Delta

## ADDED Requirements

### Requirement: Управление household в консоли

Консоль SHALL показывать активные household с названием, часовым поясом,
наличием владельца, числом участников, открытых задач и активных токенов, без
содержимого задач. Создание и удаление household MUST подчиняться тем же
правилам, что в CLI: в `single` второй активный household MUST NOT создаваться,
удаление MUST быть мягким и MUST отзывать токены и приглашения.

#### Scenario: Второй household в single

- **WHEN** в режиме `single` активный household есть и администратор пытается
  создать ещё один
- **THEN** консоль отказывает и объясняет причину
- **AND** ничего не меняется

#### Scenario: Создание в multi

- **WHEN** в режиме `multi` администратор создаёт household «Дача»
- **THEN** создаются household и списки «Задачи», «Покупки» и «Календарь»
- **AND** консоль предлагает выпустить ссылку-claim владельца

#### Scenario: Удаление household

- **WHEN** администратор подтверждает удаление household вводом его названия
- **THEN** household и участники помечены удалёнными
- **AND** токены и приглашения отозваны
- **AND** в аудите событие удаления с системным актором

### Requirement: Подтверждение опасных действий в консоли

Удаление household MUST требовать ввода его названия; отзыв токена MUST
требовать отдельного подтверждения. Запрос без подтверждения MUST NOT менять
данные.

#### Scenario: Удаление с неверным названием

- **WHEN** администратор вводит в подтверждение название, отличное от названия
  household
- **THEN** household не удаляется
- **AND** консоль сообщает о несовпадении

#### Scenario: Отзыв без подтверждения

- **WHEN** приходит запрос отзыва токена без подтверждения
- **THEN** токен остаётся активным

### Requirement: Участники в консоли

Консоль SHALL показывать участников household (имя, роль, дату вступления) и
добавлять участника по Telegram ID с ролью `owner` или `member` по правилам CLI:
событие `member_joined`, отказ для Telegram ID из другого household и для
второго владельца. Telegram ID MUST показываться только последними четырьмя
цифрами.

#### Scenario: Добавление участника

- **WHEN** администратор добавляет Telegram ID `123456789` с ролью `member`
- **THEN** участник появляется в списке
- **AND** в журнале членства событие `member_joined` с системным актором

#### Scenario: Неверный Telegram ID

- **WHEN** администратор добавляет участника с Telegram ID `0`
- **THEN** консоль отказывает с `422`
- **AND** участник не добавляется

#### Scenario: Второй владелец

- **WHEN** администратор добавляет участника с ролью `owner` в household с
  владельцем
- **THEN** консоль отказывает и предлагает передачу владения в боте
- **AND** ничего не меняется

#### Scenario: Telegram ID в списке

- **WHEN** открыт список участников
- **THEN** у участника с Telegram ID `123456789` показано `…6789`

### Requirement: API-токены в консоли

Консоль SHALL показывать токены household (имя, префикс, scopes, время
последнего использования, состояние), выпускать токен с выбором scopes и
необязательным сроком и отзывать токен. Отзыв MUST применяться только к токену
household, открытого в консоли. Открытое значение MUST показываться один раз и
MUST NOT сохраняться; события выпуска и отзыва MUST записываться в аудит без
значения токена.

#### Scenario: Выпуск токена

- **WHEN** администратор выпускает токен «Home Assistant» со scopes `ha:read`,
  `ha:write`
- **THEN** консоль показывает значение один раз
- **AND** после перезагрузки страницы значение недоступно, виден только префикс

#### Scenario: Отзыв токена

- **WHEN** администратор подтверждает отзыв токена
- **THEN** запросы с этим токеном получают `401`
- **AND** в списке токен помечен отозванным

#### Scenario: Токен другого household

- **WHEN** запрос отзыва на странице household «Дача» указывает токен household
  «Квартира»
- **THEN** ответ — `404`
- **AND** токен остаётся активным

### Requirement: Очереди в консоли

Консоль SHALL показывать число заданий по статусам для обновлений Telegram,
исходящих сообщений, разборов и доставок уведомлений и возраст самого старого
готового обновления. Возраст сверх порога readiness MUST выделяться только
тогда, когда readiness сама применяет порог: порог задан и бот работает.
Страница MUST NOT показывать содержимое заданий и MUST обновляться без
перезагрузки.

#### Scenario: Задержка очереди

- **WHEN** самое старое готовое обновление ждёт 7 минут при пороге 5 минут и бот
  работает
- **THEN** страница выделяет возраст как превышающий порог readiness
- **AND** текст обновлений не показывается

#### Scenario: Бот выключен

- **WHEN** бот выключен, а самое старое готовое обновление ждёт 7 минут при
  пороге 5 минут
- **THEN** страница показывает возраст без выделения
- **AND** не пишет, что порог readiness превышен

### Requirement: Выгрузка household в консоли

Консоль SHALL отдавать выгрузку household файлом JSON в том же формате, что
`tasklerq admin export`. Выгрузка MUST NOT содержать хеши токенов и секреты,
ответ MUST запрещать кеширование. Событие выгрузки MUST записываться в аудит без
содержимого — и при выгрузке из консоли, и при выгрузке через CLI.

#### Scenario: Выгрузка

- **WHEN** администратор скачивает выгрузку household
- **THEN** файл содержит списки, задачи и настройки household
- **AND** не содержит хешей токенов и секретов
- **AND** ответ содержит `Cache-Control: no-store`
