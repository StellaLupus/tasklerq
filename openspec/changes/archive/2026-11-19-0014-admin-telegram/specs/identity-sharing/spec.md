# Spec Delta

## MODIFIED Requirements

### Requirement: Первый запуск и создание household

Система SHALL при первом обращении пользователя без приглашения учитывать
состояние инсталляции. В режиме `single` онбординг (запрос названия household и
часового пояса) MUST запускаться только на пустой инсталляции. Если задан
`BOOTSTRAP_OWNER_TELEGRAM_ID`, онбординг MUST быть доступен только этому
Telegram ID. Пользователь, открывший действующую ссылку-claim консоли, MUST
получать онбординг независимо от `BOOTSTRAP_OWNER_TELEGRAM_ID`. В режиме
`single`, если учётка администратора консоли создана, онбординг без ссылки-claim
MUST быть доступен только `BOOTSTRAP_OWNER_TELEGRAM_ID`. В режиме `multi`
онбординг без ссылки-claim MUST оставаться доступным каждому.

#### Scenario: Ограничение первого владельца

- **WHEN** задан `BOOTSTRAP_OWNER_TELEGRAM_ID=111` и пользователь с Telegram ID
  `222` отправляет `/start` на пустой инсталляции
- **THEN** бот сообщает, что пространство ещё не настроено, и предлагает
  обратиться к администратору
- **AND** не раскрывает ожидаемый Telegram ID
- **AND** household не создаётся

#### Scenario: Первый владелец из конфигурации

- **WHEN** задан `BOOTSTRAP_OWNER_TELEGRAM_ID=111` и пользователь с Telegram ID
  `111` отправляет `/start` на пустой инсталляции
- **THEN** бот запускает онбординг
- **AND** после подтверждения пользователь становится владельцем

#### Scenario: Онбординг по ссылке-claim

- **WHEN** на пустой инсталляции пользователь с Telegram ID `222` открывает
  действующую ссылку-claim, а задан `BOOTSTRAP_OWNER_TELEGRAM_ID=111`
- **THEN** бот запускает онбординг
- **AND** ссылка становится использованной только в момент создания household

#### Scenario: Учётка администратора закрывает правило первого написавшего

- **WHEN** в режиме `single` учётка администратора создана,
  `BOOTSTRAP_OWNER_TELEGRAM_ID` не задан, и пользователь отправляет `/start`
  без ссылки на пустой инсталляции
- **THEN** бот сообщает, что пространство ещё не настроено, и предлагает
  обратиться к администратору
- **AND** household не создаётся

#### Scenario: Онбординг в multi при созданной учётке

- **WHEN** в режиме `multi` учётка администратора создана, и неизвестный
  пользователь отправляет `/start` без ссылки и без приглашения
- **THEN** бот запускает онбординг, как раньше

### Requirement: Обращение к уже созданному household

Если household уже есть, система MUST NOT создавать новый:

- при наличии владельца пользователь получает предложение попросить приглашение;
- если владельца нет и пользователь открыл действующую ссылку-claim этого
  household или его Telegram ID совпадает с `BOOTSTRAP_OWNER_TELEGRAM_ID`, он
  становится владельцем;
- если владельца нет, а `BOOTSTRAP_OWNER_TELEGRAM_ID` задан и не совпадает с
  отправителем, бот сообщает, что пространство ещё не настроено;
- в остальных случаях без владельца бот показывает CLI-команду добавления
  владельца с подставленным Telegram ID пользователя (а при созданной учётке
  администратора — также предложение попросить ссылку у администратора) и MUST
  NOT назначать владельца сам.

#### Scenario: Пространство уже есть

- **WHEN** в режиме `single` неизвестный пользователь отправляет `/start` без
  приглашения, а у существующего household есть владелец
- **THEN** бот сообщает, что это частное пространство, и предлагает попросить
  приглашение у владельца
- **AND** household не создаётся

#### Scenario: Household без владельца

- **WHEN** в режиме `single` пользователь с Telegram ID `123456789` отправляет
  `/start` без приглашения, а единственный household не имеет владельца и
  `BOOTSTRAP_OWNER_TELEGRAM_ID` не задан
- **THEN** бот показывает команду
  `tasklerq admin user add --telegram-id 123456789 --role owner`
- **AND** не назначает пользователя владельцем и не создаёт household

#### Scenario: Владелец, добавленный администратором

- **WHEN** администратор выполняет
  `tasklerq admin user add --telegram-id <id> --role owner` для household без
  владельца
- **THEN** пользователь создаётся с ролью `owner`, а его чат совпадает с
  Telegram ID
- **AND** при первом обращении к боту он видит главное меню без онбординга

#### Scenario: Второй владелец через CLI

- **WHEN** администратор добавляет `--role owner` в household, где владелец уже есть
- **THEN** команда завершается ошибкой `409`
- **AND** владение передаётся штатным способом

#### Scenario: Владелец по ссылке-claim

- **WHEN** household создан в консоли без владельца, и пользователь открывает
  его действующую ссылку-claim
- **THEN** пользователь создаётся с ролью `owner`, а его чат совпадает с
  Telegram ID
- **AND** бот показывает главное меню без онбординга

#### Scenario: Первый владелец из конфигурации для household без владельца

- **WHEN** household создан в консоли без владельца, задан
  `BOOTSTRAP_OWNER_TELEGRAM_ID=111`, и пользователь `111` отправляет `/start`
- **THEN** пользователь становится владельцем и видит главное меню

#### Scenario: Чужой Telegram ID при заданном первом владельце

- **WHEN** household без владельца, задан `BOOTSTRAP_OWNER_TELEGRAM_ID=111`, и
  пользователь `222` отправляет `/start` без ссылки
- **THEN** бот сообщает, что пространство ещё не настроено
- **AND** не раскрывает ожидаемый Telegram ID

#### Scenario: Одновременный claim

- **WHEN** два пользователя одновременно открывают одну ссылку-claim
- **THEN** владельцем становится ровно один
- **AND** второй видит экран, как при `/start` без ссылки
