## Purpose

Описывает тонкий custom component Home Assistant, который публикует списки
Tasklerq как сущности `todo` и задачи со сроком как сущность `calendar`,
синхронизирует изменения через REST API и предоставляет сервис
`tasklerq.capture`. Основной голосовой сценарий — HA Assist: распознанный текст
передаётся в Tasklerq, ответ озвучивается.

## ADDED Requirements

### Requirement: Установка и совместимость

Система SHALL поставлять custom component `tasklerq` из отдельного репозитория
`tasklerq-ha` со своими версиями и релизами; установка — HACS как
пользовательский репозиторий или копирование в `custom_components/tasklerq`.
Компонент MUST поддерживать Home Assistant Container и MUST NOT требовать
Supervisor, add-on или ingress. Компонент MUST объявлять минимальную
поддерживаемую версию Home Assistant и MUST предупреждать пользователя при
несовместимой версии.

#### Scenario: Установка через HACS

- **WHEN** пользователь добавляет репозиторий `tasklerq-ha` в HACS и
  устанавливает компонент
- **THEN** Home Assistant обнаруживает `custom_components/tasklerq`
- **AND** после перезапуска доступна интеграция Tasklerq

#### Scenario: Ручная установка

- **WHEN** пользователь копирует каталог `custom_components/tasklerq` в
  `/config/custom_components/`
- **THEN** после перезапуска Home Assistant интеграция доступна
- **AND** не требуется установка add-on

#### Scenario: Несовместимая версия

- **WHEN** версия Home Assistant ниже минимальной
- **THEN** компонент не загружается
- **AND** в логе появляется понятное предупреждение с требуемой версией

### Requirement: Настройка подключения

Система SHALL предоставлять config flow, запрашивающий базовый URL Tasklerq и
API-токен. При настройке компонент MUST проверить доступность, токен и права
запросом `GET /api/v1/household`; при ошибке MUST показать понятную причину. Успешная настройка MUST использовать идентификатор household как
`unique_id` и MUST не позволять создать две интеграции для одного household.
При ответе `401` компонент MUST запускать reauth flow. В options MUST быть
доступны интервал polling от 30 до 300 секунд и горизонт календаря от 7 до 90
дней.

#### Scenario: Успешная настройка

- **WHEN** пользователь вводит корректный URL и токен
- **THEN** интеграция создаётся
- **AND** компонент загружает списки и создаёт сущности

#### Scenario: Неверный токен

- **WHEN** Tasklerq возвращает `401` при настройке
- **THEN** форма показывает «Неверный токен»
- **AND** интеграция не создаётся

#### Scenario: Повторная настройка

- **WHEN** пользователь пытается добавить второй экземпляр для того же
  household
- **THEN** Home Assistant сообщает, что интеграция уже настроена
- **AND** дубликат не создаётся

#### Scenario: Истечение токена

- **WHEN** во время работы Tasklerq возвращает `401`
- **THEN** компонент запускает reauth flow
- **AND** сущности становятся недоступными до устранения проблемы

### Requirement: Todo-сущности по спискам

Система SHALL создавать одну сущность `todo` для каждого неархивированного
списка household. `unique_id` сущности MUST быть стабильным и строиться из
идентификатора household и идентификатора списка. Сущность MUST поддерживать
создание, редактирование, удаление и завершение позиций. Поля `title`,
`description`, `due` и `status` MUST синхронизироваться в обе стороны. При
переименовании списка сущность MUST сохранять `unique_id` и менять отображаемое
имя. При архивировании списка сущность MUST удаляться из реестра, а данные MUST
оставаться в Tasklerq.

#### Scenario: Создание списка

- **WHEN** в Tasklerq появляется новый список «Дача»
- **THEN** после обновления координатора в Home Assistant появляется
  `todo.dacha`
- **AND** сущность содержит открытые позиции списка

#### Scenario: Создание позиции из Home Assistant

- **WHEN** пользователь создаёт позицию «Купить лампочку» через `todo`
- **THEN** Tasklerq создаёт позицию в соответствующем списке
- **AND** она появляется в Telegram

#### Scenario: Завершение из Home Assistant

- **WHEN** пользователь отмечает позицию выполненной в `todo`
- **THEN** Tasklerq завершает её с автором `Home Assistant`
- **AND** изменение отражается в Telegram

#### Scenario: Переименование списка

- **WHEN** владелец переименовывает список в Tasklerq
- **THEN** имя сущности в Home Assistant обновляется
- **AND** `unique_id` и история сущности сохраняются

### Requirement: Сервис capture

Компонент SHALL регистрировать сервис `tasklerq.capture` с полями `text`
(обязательно), `source` (`ha_voice`/`ha_automation`, по умолчанию
`ha_automation`), `mode` (`auto`/`draft`, по умолчанию `auto`), `hint`
(`tasks`/`shopping`/`checklist`), `list_id` и `idempotency_key`. Сервис MUST
вызывать `POST /api/v1/capture` с токеном интеграции и MUST возвращать ответ
(`status`, `speech`, `items`, `draft_id`, `capture_id`) через
`SupportsResponse.OPTIONAL`, чтобы автоматизация могла вызвать сервис и без
`response_variable`. Сервис MUST NOT требовать Telegram. При ошибке MUST
возвращаться `HomeAssistantError` с русским текстом, не теряя исходный текст.

#### Scenario: Создание задачи через сервис

- **WHEN** автоматизация вызывает `tasklerq.capture` с текстом «позвонить маме
  завтра»
- **THEN** компонент отправляет запрос в Tasklerq
- **AND** возвращает `status=applied`, `speech` и созданный элемент

#### Scenario: Режим черновика

- **WHEN** сервис вызван с `mode=draft`
- **THEN** Tasklerq возвращает `draft_id` и элементы
- **AND** элементы не создаются до подтверждения

#### Scenario: Автоматизация без голоса

- **WHEN** автоматизация вызывает сервис без поля `source`
- **THEN** компонент передаёт `source=ha_automation`
- **AND** элемент получает источник `ha_automation`

#### Scenario: Tasklerq недоступен

- **WHEN** запрос к Tasklerq завершается ошибкой соединения
- **THEN** сервис возвращает `HomeAssistantError`
- **AND** не создаёт частичное состояние

#### Scenario: Идемпотентность

- **WHEN** компонент повторяет запрос после сетевой ошибки
- **THEN** он передаёт тот же `idempotency_key`
- **AND** Tasklerq не создаёт дубликат

### Requirement: Голосовой сценарий Assist

Система SHALL поддерживать сценарий Home Assistant Assist: пользовательские
предложения Assist (custom sentences) вызывают `intent_script`, который вызывает
`tasklerq.capture` и озвучивает `speech` из ответа сервиса. Пример конфигурации
MUST поставляться в документации и примере пакета. Сценарий MUST работать без
Telegram и MUST NOT требовать включения Assist-инструментов (`llm_hass_api`) у
AI Task.

#### Scenario: Покупка голосом

- **WHEN** пользователь говорит «купи молоко и хлеб»
- **THEN** Assist вызывает `tasklerq.capture` с `hint=shopping`
- **AND** Tasklerq создаёт две покупки
- **AND** Assist озвучивает «Добавил две покупки»

#### Scenario: Задача голосом

- **WHEN** пользователь говорит «добавь задачу позвонить маме завтра»
- **THEN** создаётся задача со сроком «завтра»
- **AND** ответ озвучивается без упоминания Telegram

#### Scenario: LLM недоступна

- **WHEN** AI Task не отвечает
- **THEN** Tasklerq создаёт одну позицию из исходного текста
- **AND** Assist озвучивает «Записал как есть»

#### Scenario: Без Assist-инструментов

- **WHEN** у AI Task не включён `llm_hass_api`
- **THEN** голосовой capture всё равно работает
- **AND** LLM не получает инструментов управления HA

#### Scenario: LLM-агент в Assist

- **WHEN** в Assist выбран LLM-агент, который не использует пользовательские предложения (custom sentences) Assist
- **THEN** документация предлагает отдельный pipeline с агентом Home Assistant
  или явное действие агента
- **AND** разбор Tasklerq продолжает работать без Assist-инструментов

### Requirement: Отмена последнего голосового capture

Компонент SHALL регистрировать сервис `tasklerq.undo_last_capture`, который
отменяет последний применённый capture источника `ha_voice` за последние 10
минут. Ответ MUST содержать количество удалённых элементов и `speech`; при
отсутствии подходящего capture MUST возвращаться понятное сообщение, а не
ошибка.

#### Scenario: Отмена голосом

- **WHEN** пользователь говорит «отмени последнее добавление» в течение 10 минут
- **THEN** компонент вызывает отмену последнего голосового capture
- **AND** озвучивает количество удалённых элементов

#### Scenario: Нечего отменять

- **WHEN** за последние 10 минут не было голосовых capture
- **THEN** сервис возвращает `count=0`
- **AND** Assist озвучивает, что отменять нечего

#### Scenario: Элемент уже изменён

- **WHEN** последний capture содержит изменённый элемент
- **THEN** Tasklerq возвращает `409`
- **AND** компонент показывает понятную ошибку, не удаляя элементы частично

### Requirement: Дополнительные поля задач

Система SHALL сохранять приоритет, теги, исполнителя и правило повторения,
которые не представлены нативно в модели `todo` Home Assistant. Эти поля MUST
быть доступны в атрибуте сущности `tasklerq_items` в виде списка объектов,
соответствующих позициям списка. Изменение нативных полей через Home Assistant
MUST NOT терять дополнительные поля.

#### Scenario: Приоритет и теги

- **WHEN** задача имеет приоритет `high` и тег `дом`
- **THEN** атрибут `tasklerq_items` содержит эти значения
- **AND** завершение задачи из Home Assistant не удаляет их

#### Scenario: Исполнитель

- **WHEN** задача назначена участнику
- **THEN** атрибут `tasklerq_items` содержит отображаемое имя исполнителя
- **AND** назначение остаётся доступным в Telegram

### Requirement: Календарная сущность

Система SHALL создавать одну read-only сущность `calendar` для задач со сроком.
События MUST содержать название, описание, начало, конец, признак `all_day` и
идентификатор задачи. Задачи со временем MUST отображаться как события со
временем; вседневные задачи MUST отображаться как all-day события.
Повторяющиеся задачи MUST разворачиваться в отдельные события на горизонте,
настроенном в options. Сущность MUST NOT предлагать создание, редактирование
или удаление событий.

#### Scenario: Событие со временем

- **WHEN** задача назначена на `2026-11-03 18:00`
- **THEN** календарь показывает событие с началом в `18:00`
- **AND** событие содержит название задачи

#### Scenario: Вседневная задача

- **WHEN** задача имеет `due_date = 2026-11-03`
- **THEN** календарь показывает all-day событие на эту дату
- **AND** событие не занимает время в сетке дня

#### Scenario: Повторяющаяся задача

- **WHEN** задача повторяется еженедельно по вторникам
- **THEN** календарь показывает отдельные события на каждом вторнике в
  пределах горизонта
- **AND** события имеют разные детерминированные ключи

#### Scenario: Попытка редактирования

- **WHEN** пользователь пытается создать событие через сущность Tasklerq
- **THEN** сущность не предоставляет такую возможность
- **AND** Tasklerq не создаёт задачу из события календаря

### Requirement: Синхронизация и конфликты

Система SHALL синхронизировать данные через polling координатора с интервалом
по умолчанию 60 секунд. Координатор MUST использовать инкрементальный снапшот
по курсору `since` и MUST выполнять полную синхронизацию при первом запуске,
смене токена и не реже одного раза в сутки. Изменения из Home Assistant MUST
передавать текущую версию ресурса. При `409 Conflict` компонент MUST обновить
данные и MUST показать пользователю ошибку о конфликте, не применяя изменение
молча.

#### Scenario: Изменение в Tasklerq

- **WHEN** задача изменена в Telegram
- **THEN** не позднее следующего polling-цикла Home Assistant показывает новое
  состояние
- **AND** изменение не требует перезапуска Home Assistant

#### Scenario: Конфликт версий

- **WHEN** пользователь редактирует позицию в Home Assistant, а другая сторона
  уже изменила её
- **THEN** Tasklerq возвращает `409`
- **AND** компонент обновляет координатор и показывает ошибку конфликта

#### Scenario: Удалённая позиция

- **WHEN** позиция удалена в Tasklerq
- **THEN** при следующем снапшоте Home Assistant удаляет её из сущности
- **AND** не пытается восстановить её при следующей записи

### Requirement: Ошибки и доступность

Система SHALL помечать сущности недоступными, если Tasklerq недоступен или
возвращает `5xx`. Координатор MUST повторять попытки с экспоненциальной
задержкой от 30 секунд до 5 минут и MUST восстанавливаться автоматически.
Операции записи MUST возвращать `HomeAssistantError` с понятным русским
сообщением и MUST NOT создавать частичное состояние. Токен MUST NOT попадать в
логи.

#### Scenario: Tasklerq недоступен

- **WHEN** координатор не может подключиться к Tasklerq
- **THEN** сущности становятся `unavailable`
- **AND** Home Assistant продолжает попытки с задержкой

#### Scenario: Восстановление

- **WHEN** Tasklerq снова доступен
- **THEN** координатор успешно обновляется
- **AND** сущности возвращаются в доступное состояние

#### Scenario: Ошибка записи

- **WHEN** создание позиции завершается ошибкой `422`
- **THEN** Home Assistant показывает сообщение с причиной
- **AND** позиция не появляется в списке

### Requirement: Безопасность токена

Система SHALL использовать API-токен с областью действия `ha:read` для чтения и
`ha:write` для записи. Компонент MUST передавать токен только в заголовке
`Authorization: Bearer`, MUST NOT писать его в логи и MUST NOT сохранять в
открытом виде в diagnostics. При отзыве токена компонент MUST получать `401` и
переходить в reauth. Соединение с Tasklerq MUST использовать HTTPS, если
сервис доступен за пределами локальной сети.

#### Scenario: Только чтение

- **WHEN** настроен токен только с `ha:read`
- **THEN** сущности отображаются
- **AND** попытка создать позицию возвращает ошибку прав

#### Scenario: Отзыв токена

- **WHEN** владелец отзывает токен в Tasklerq
- **THEN** следующий запрос Home Assistant получает `401`
- **AND** запускается reauth flow

#### Scenario: Diagnostics без секретов

- **WHEN** пользователь скачивает diagnostics интеграции
- **THEN** файл содержит URL, интервал, версию и количество сущностей
- **AND** не содержит токен и содержимое задач

### Requirement: Диагностика

Система SHALL предоставлять diagnostics-файл с информацией о конфигурации
интеграции, списке сущностей, времени последней успешной синхронизации,
количестве позиций и версии компонента. Diagnostics MUST быть очищен от токена,
URL с учётными данными и пользовательского контента. Ошибки синхронизации MUST
содержать код и время, но MUST NOT содержать тело ответа с персональными
данными.

#### Scenario: Успешная диагностика

- **WHEN** интеграция работает штатно
- **THEN** diagnostics показывает время последней синхронизации и список
  сущностей
- **AND** не содержит токен

#### Scenario: Ошибка синхронизации

- **WHEN** последняя синхронизация завершилась ошибкой
- **THEN** diagnostics содержит код ошибки и время
- **AND** не содержит названий задач и имён участников
