## Purpose

Описывает совместные списки покупок и дополнительные чек-листы: добавление
позиций, количество, отметку покупки, очистку и работу нескольких участников.

## ADDED Requirements

### Requirement: Список покупок по умолчанию

Система SHALL создавать household список покупок с названием «Покупки» и kind
`shopping` при создании household. Список MUST быть доступен всем участникам,
не может быть удалён или архивирован, но может быть переименован. Очистка
выполненных позиций MUST быть доступна владельцу и участникам.

#### Scenario: Создание household

- **WHEN** создаётся новый household
- **THEN** система создаёт список «Покупки» с kind `shopping`
- **AND** помечает его как список по умолчанию

#### Scenario: Переименование

- **WHEN** владелец переименовывает список покупок в «Продукты»
- **THEN** новое название отображается у всех участников и в Home Assistant
- **AND** kind и идентификатор списка не меняются

#### Scenario: Попытка удаления

- **WHEN** владелец пытается удалить список покупок по умолчанию
- **THEN** система возвращает `409` с объяснением
- **AND** список остаётся доступным

### Requirement: Добавление позиции

Система SHALL добавлять позицию в список покупок при наличии названия длиной от
1 до 200 символов. Количество MUST быть положительным числом не больше 9999 с
точностью до трёх знаков после запятой; по умолчанию используется `1`.
Единица измерения MUST быть строкой длиной от 0 до 16 символов; по умолчанию
используется «шт». Позиция может содержать заметку длиной до 500 символов,
исполнителя из числа участников household и срок; срок отображается в списке,
но не добавляет позицию в календарь задач.

#### Scenario: Добавление с количеством

- **WHEN** участник добавляет «Молоко», количество `2`, единицу «л»
- **THEN** система создаёт открытую позицию с количеством `2 л`
- **AND** позиция появляется в общем списке и в Home Assistant

#### Scenario: Значение по умолчанию

- **WHEN** участник добавляет «Хлеб» без количества и единицы
- **THEN** система сохраняет количество `1` и единицу «шт»

#### Scenario: Некорректное количество

- **WHEN** участник указывает количество `0`, `-1` или `10000`
- **THEN** система возвращает ошибку валидации
- **AND** позиция не создаётся

### Requirement: Обнаружение дубликатов

Система SHALL сравнивать новую позицию с открытыми позициями того же списка по
нормализованному названию без учёта регистра и лишних пробелов. При совпадении
система MUST предложить увеличить количество существующей позиции или добавить
отдельную позицию. Автоматическое объединение без выбора пользователя
запрещено.

#### Scenario: Поиск дубликата

- **WHEN** участник добавляет «молоко», а в списке уже есть открытая позиция
  «Молоко»
- **THEN** бот показывает выбор «Увеличить количество» или «Добавить отдельно»
- **AND** до выбора ничего не сохраняется

#### Scenario: Увеличение количества

- **WHEN** участник выбирает «Увеличить количество» для позиции `2 л`
- **THEN** количество становится `3 л`
- **AND** создаётся событие изменения позиции

#### Scenario: Отдельная позиция

- **WHEN** участник выбирает «Добавить отдельно»
- **THEN** создаётся вторая позиция с тем же названием
- **AND** обе позиции остаются в списке

### Requirement: Отметка покупки и возврат

Система SHALL переводить позицию в статус `done` при отметке покупки, фиксируя
время и участника. Выполненная позиция MUST оставаться в списке в разделе
«Куплено» до очистки. Повторная отметка MUST быть идемпотентной. Участник может
вернуть позицию в статус `open`; возврат MUST восстанавливать прежнюю позицию в
списке.

#### Scenario: Отметка покупки

- **WHEN** участник отмечает «Молоко» купленным
- **THEN** позиция получает статус `done`, время и автора
- **AND** перемещается в раздел «Куплено»

#### Scenario: Повторная отметка

- **WHEN** клиент повторно отправляет отметку уже купленной позиции
- **THEN** система возвращает успешный результат без изменения времени
- **AND** не создаёт дубликат события

#### Scenario: Возврат позиции

- **WHEN** участник возвращает купленную позицию в список
- **THEN** позиция получает статус `open`
- **AND** её количество и единица сохраняются

### Requirement: Очистка выполненных

Система SHALL позволять очистить все выполненные позиции списка. Если
выполненных позиций больше пяти, система MUST запросить подтверждение с
количеством. Очистка MUST быть мягким удалением с возможностью отмены в течение
10 минут. Очистка MUST создавать событие с количеством удалённых позиций.

#### Scenario: Очистка с подтверждением

- **WHEN** в списке шесть выполненных позиций и участник нажимает «Очистить»
- **THEN** бот показывает подтверждение «Удалить 6 позиций?»
- **AND** до подтверждения ничего не удаляется

#### Scenario: Очистка без подтверждения

- **WHEN** в списке две выполненные позиции и участник нажимает «Очистить»
- **THEN** система сразу выполняет мягкое удаление
- **AND** показывает кнопку «Отменить»

#### Scenario: Отмена очистки

- **WHEN** участник отменяет очистку в течение 10 минут
- **THEN** все удалённые позиции восстанавливаются
- **AND** создаётся компенсирующее событие

### Requirement: Дополнительные списки

Система SHALL разрешать создавать дополнительные списки с kind `shopping` или
`checklist`. В household может быть не более 20 списков, включая списки по
умолчанию. Владелец может переименовать, архивировать и удалить дополнительный
список; участник может создать дополнительный список и переименовать его.
Архивированный список MUST быть скрыт из бота, поиска и Home Assistant, но его
данные MUST сохраняться. Удаление списка MUST быть мягким и каскадным для его
позиций.

#### Scenario: Создание списка

- **WHEN** участник создаёт список «Дача» с kind `checklist`
- **THEN** список появляется в главном меню и в Home Assistant
- **AND** участник становится его автором

#### Scenario: Архивирование

- **WHEN** владелец архивирует список «Дача»
- **THEN** список исчезает из меню и Home Assistant
- **AND** позиции сохраняются в базе

#### Scenario: Превышение лимита списков

- **WHEN** в household уже 20 списков и участник создаёт ещё один
- **THEN** система возвращает `409` с объяснением
- **AND** новый список не создаётся

### Requirement: Совместная работа

Система SHALL показывать все неархивированные списки всем участникам
household. Любой участник может добавлять, редактировать, отмечать и возвращать
позиции. Назначение позиции MUST быть доступно только участнику household;
исполнитель получает уведомление о назначении. Изменения одного участника MUST
становиться видимыми другим при следующем обновлении экрана или polling
Home Assistant.

#### Scenario: Общая видимость

- **WHEN** один участник добавляет позицию в список покупок
- **THEN** другой участник видит её при следующем открытии списка
- **AND** позиция доступна в Home Assistant

#### Scenario: Назначение покупки

- **WHEN** участник назначает позицию «Купить торт» другому участнику
- **THEN** исполнитель получает уведомление
- **AND** в позиции отображается исполнитель

#### Scenario: Изоляция household

- **WHEN** участник другого household запрашивает позицию по идентификатору
- **THEN** система возвращает `404`
- **AND** данные не раскрываются

### Requirement: Поиск по позициям

Система SHALL включать позиции покупок и чек-листов в общий поиск по названию
и заметкам без учёта регистра. Результаты MUST содержать название списка и
статус позиции и MUST поддерживать фильтр по списку и статусу.

#### Scenario: Поиск покупки

- **WHEN** участник ищет «молоко» в общем поиске
- **THEN** система возвращает позиции «Молоко» из всех доступных списков
- **AND** показывает, в каком списке находится каждая позиция

#### Scenario: Поиск только выполненных

- **WHEN** участник применяет фильтр «Куплено»
- **THEN** система возвращает только выполненные позиции
- **AND** исключает удалённые и архивные списки
