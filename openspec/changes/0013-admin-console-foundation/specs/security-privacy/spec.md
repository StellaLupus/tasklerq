# Spec Delta

## MODIFIED Requirements

### Requirement: Секреты и доступ к инфраструктуре

Система SHALL хранить секреты в переменных окружения, env-file с правами `0600`,
Docker secrets или в базе в зашифрованном виде ключом `TASKLERQ_SECRET_KEY`,
который задаётся только окружением. Секреты MUST NOT попадать в репозиторий,
образ, логи, diagnostics, трассировки, сообщения об ошибках и в выгрузки
household; единственное исключение — setup-код консоли, который выводится в лог,
пока учётной записи администратора нет. Секреты MUST поддерживать ротацию без
пересборки образа. Зависимости MUST проверяться на известные уязвимости в CI.

#### Scenario: Diagnostics

- **WHEN** скачивается diagnostics Home Assistant
- **THEN** токен и пароль базы отсутствуют
- **AND** URL не содержит учётных данных

#### Scenario: Ротация токена бота

- **WHEN** администратор меняет `TELEGRAM_BOT_TOKEN`
- **THEN** сервис перезапускается с новым токеном
- **AND** старый токен перестаёт использоваться
- **AND** webhook перерегистрируется

#### Scenario: Уязвимая зависимость

- **WHEN** CI обнаруживает критическую уязвимость в зависимости
- **THEN** сборка блокируется до обновления или явного исключения
- **AND** исключение фиксируется с обоснованием

#### Scenario: Резервная копия базы без ключа

- **WHEN** резервная копия базы с сохранённым токеном слота восстановлена на
  другом сервере без `TASKLERQ_SECRET_KEY`
- **THEN** токен слота не может быть прочитан
- **AND** остальные данные восстановлены полностью

### Requirement: Аудит безопасности

Система SHALL записывать события безопасности: неудачную аутентификацию
webhook и API, превышение лимитов, отзыв и создание токенов, изменение ролей,
удаление участников и household, ошибки LLM-валидации, а также события консоли
оператора: вход, неудачный вход, неудачный ввод setup-кода, создание учётной
записи, смену пароля, выпуск ссылки восстановления, изменение настроек (имя
настройки без значения). Неудачные входы в консоль MUST учитываться в пороге
уведомления об отказах аутентификации. События MUST
содержать время, тип, идентификатор актора (если известен) и результат, но MUST
NOT содержать секреты и полный пользовательский контент. События MUST
храниться не менее 90 дней. Система MUST позволять настроить уведомление при
превышении порога отказов аутентификации.

#### Scenario: Всплеск отказов

- **WHEN** за 5 минут происходит более 50 отказов webhook
- **THEN** система увеличивает метрику и создаёт событие безопасности
- **AND** администратор может получить уведомление

#### Scenario: Создание токена

- **WHEN** администратор создаёт API-токен
- **THEN** событие содержит имя токена и области действия
- **AND** не содержит сам токен

#### Scenario: Изменение роли

- **WHEN** владелец передаёт владение
- **THEN** событие содержит прежнюю и новую роль
- **AND** событие доступно в журнале

#### Scenario: Изменение настройки в консоли

- **WHEN** администратор меняет токен основного слота LLM
- **THEN** событие содержит имя настройки и отметку, что это секрет
- **AND** не содержит ни прежнего, ни нового значения
