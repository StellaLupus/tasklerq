# Proposal

## Why

Первая установка Tasklerq сейчас — это `.env` примерно из сорока переменных и
13 шагов `docs/deployment.md` §5 и §9. Любая смена LLM-слота требует правки
файла и `force-recreate` контейнера. Для семейной инсталляции это главный
барьер: значения вроде адреса и модели слота или токена слота оператор вводит
руками, не видя, работают ли они, а проверка слота доступна только как CLI
внутри контейнера.

Пункт roadmap v0.3 «Веб-UI для управления household и токенами» превращается в
консоль оператора инсталляции. Этот change закладывает её фундамент: отдельный
закрытый по умолчанию listener, учётную запись администратора, хранилище
настроек в базе с шифрованием секретов и первый мастер, которого хватает для
сценария «только Home Assistant, без бота». Telegram в мастере (change 0014) и
экраны управления (change 0015) строятся на этом фундаменте.

## What Changes

- Второй HTTP-listener `ADMIN_BIND_ADDR` (по умолчанию `0.0.0.0:8081` внутри
  контейнера, значение `disabled` выключает консоль). Маршруты консоли есть
  только на нём; публичный listener о них не знает. Наружу консоль выходит
  только если оператор сам опубликует порт или заведёт правило прокси.
- Учётная запись администратора инсталляции: одна, с именем и паролем
  (argon2id), не связанная с `users` и Telegram. Действия консоли выполняются от
  системного актора, как в `tasklerq admin`.
- Первый вход по одноразовому setup-коду: код выводится в лог при старте, пока
  учётки нет, и выдаётся командой `tasklerq admin setup-code`. Это явное и
  единственное исключение из запрета секретов в логе.
- Сессии в cookie (`HttpOnly`, `SameSite=Strict`, `Secure` за доверенным
  HTTPS-прокси), точная сверка `Origin` на всех изменяющих запросах (включая
  вход), лимит неудачных попыток на клиента, аудит входов и изменений настроек.
  Доверенные прокси консоли задаются явно `ADMIN_TRUSTED_PROXIES`; по умолчанию
  заголовкам `X-Forwarded-*` консоль не доверяет.
- Смена пароля в консоли.
- Восстановление доступа: `tasklerq admin reset-password` выдаёт одноразовую
  ссылку восстановления; та же механика, что у setup-кода.
- Хранилище настроек в базе с двумя уровнями — инсталляция и household
  (household-уровень пока не используется, но схема его допускает). Секреты
  шифруются ключом `TASKLERQ_SECRET_KEY` из окружения (с поддержкой прежнего
  ключа `TASKLERQ_SECRET_KEY_OLD` на время ротации). Порядок источников:
  окружение, затем база, затем значение по умолчанию; значение из окружения в
  консоли только для чтения.
- Без ключа или с неверным ключом сервис запускается: зашифрованные настройки
  считаются недоступными (группа с нерасшифрованным секретом — целиком
  ненастроенной), readiness остаётся успешной и предупреждает
  `secret_key_missing` или `secret_undecryptable`. Ротация ключа — командой
  `tasklerq admin secret-key rotate`.
- LLM-слоты, квота и включение разбора настраиваются в консоли. Изменение
  применяется без перезапуска (hot-swap): разбор, HTTP capture, Telegram,
  квота и статус слотов берут текущий снимок конфигурации LLM.
- Умолчания окружения больше не блокируют консоль: `LLM_CAPTURE_ENABLED`
  действует, только если задан явно; слот считается заданным окружением, только
  если задан его адрес или модель. `ENV` получает умолчание `production`.
- Проверка слота smoke-набором запускается из консоли: тот же прогон, отпечаток
  и запись в `llm_slot_checks`, что у `capture-eval`; результат и статус видны
  на странице слота. `capture-eval` видит слоты, заданные в консоли;
  одновременно идёт не больше одной проверки (блокировка в базе).
- Переход повторяющихся событий выносится из Telegram-рантайма в постоянно
  работающий воркер: в сценарии «только HA» события сейчас не переходят на
  следующее вхождение.
- Мастер первого запуска: setup-код и учётка → household (в `single`, если его
  нет; пропуск — только при включённом Telegram, тогда household создаёт
  онбординг в боте) → LLM (можно пропустить) → токен для Home Assistant (показ
  один раз, можно пропустить).
- `PUBLIC_BASE_URL` становится необязательным: сейчас его значение нигде не
  используется, кроме валидации. Если задан, в production он по-прежнему обязан
  быть HTTPS.
- Обновление `docs/roadmap.md`: v0.3 — консоль оператора; консоль дома и LLM
  на уровне household перенесены в v0.5 «Семья и права»; формулировка
  «SaaS и мультитенантность» в «Явно не планируется» уточнена, чтобы не
  противоречить режиму `multi`.

## Capabilities

### New Capabilities

- `admin-console`: консоль оператора инсталляции — listener, учётная запись,
  setup-код, сессии, восстановление, хранилище настроек и мастер первого
  запуска.

### Modified Capabilities

- `deployment-operations`: «Конфигурация через окружение» (необязательные
  `ENV` и `PUBLIC_BASE_URL`, LLM из окружения или из консоли, новые
  `ADMIN_BIND_ADDR`, `ADMIN_TRUSTED_PROXIES` и `TASKLERQ_SECRET_KEY`),
  «Секреты и безопасные значения по умолчанию» (исключение для setup-кода),
  «Health и наблюдаемость» (предупреждения о ключе, слоты без перезапуска),
  «Административный CLI» (setup-код, сброс пароля, ротация ключа, настройки
  консоли).
- `security-privacy`: «Секреты и доступ к инфраструктуре» (секреты в базе под
  ключом из окружения), «Аудит безопасности» (события консоли).
- `llm-backends`: «Слоты LLM» (источник настроек и применение без перезапуска),
  «Проверка слота» (запуск из консоли, слоты из консоли в CLI, одна проверка
  одновременно).

## Impact

- Новые модули: `src/admin_console/` (роутер, сессии, мастер, страницы),
  `src/settings/` (хранилище, источники, шифрование), шаблоны HTML, встроенные
  статические файлы.
- `src/config/mod.rs` — `ADMIN_BIND_ADDR`, `TASKLERQ_SECRET_KEY`,
  необязательный `PUBLIC_BASE_URL`; `src/main.rs` — второй listener, подкоманды
  `setup-code`, `reset-password`, `secret-key rotate`.
- `src/app.rs`, `src/telegram/runtime.rs`, `src/telegram/capture_worker.rs`,
  `src/http/api/capture/`, `src/capture/slot_status.rs` — общий handle цепочки
  слотов вместо `Arc<Chain>`, зафиксированного при старте.
- `src/capture/slot_check.rs`, `src/main.rs` — прогон проверки выносится в
  библиотечную функцию, общую для CLI и консоли; CLI читает слоты из настроек.
- `src/jobs/scheduler.rs` — переход событий в отдельный постоянный воркер;
  `src/rate_limit.rs` — учёт только неудачных попыток; `src/http/client.rs` —
  общее определение клиента с параметром доверенных сетей.
- `src/http/health.rs` — предупреждения о ключе шифрования.
- Миграции: учётка и сессии администратора, одноразовые коды, настройки,
  новые значения `audit_event_type`.
- Зависимости: шаблонизатор (askama), argon2, AEAD (chacha20poly1305),
  arc-swap.
- dev-`docker-compose.yml`, `docs/deployment.md`, `docs/architecture.md`,
  `docs/roadmap.md`, `.env.example`.
- Совместимость: существующие `.env` работают как раньше. Значения из
  окружения имеют приоритет и в консоли только для чтения; строку
  `LLM_CAPTURE_ENABLED=false` из прежнего примера нужно удалить, чтобы
  управлять разбором из консоли. В production-compose порт консоли не
  опубликован, поэтому после обновления консоль снаружи контейнера недоступна,
  пока оператор не добавит строку `ports`.
