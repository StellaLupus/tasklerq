# Proposal

## Why

Из «Известных ограничений» PR 2–20 после проверки по коду остались шесть
дефектов поведения, достижимых на семейной инсталляции. Пользователь
теряет результат разбора, черновик становится недоступен, бот показывает
ложный баннер, LLM вызывается впустую, а одна стойкая ошибка SQL
останавливает все доставки уведомлений. Сюда же входит уборка
переходного правила 0005: оно становится мёртвым кодом через ~33 часа
после деплоя. Остальные пункты тех же PR оказались не дефектами. Они
перечислены в design (Non-Goals) с причинами.

## What Changes

- **Результат не теряется.** Если текущий экран не собирается (задачу или
  список удалили), баннер фонового результата с его кнопками показывается
  над главным меню. Сейчас результат молча пропадает.
- **Отмена прямого добавления покупок:**
  - «↩️ Отменить» помнит черновик, после отмены остаётся «Открыть»;
  - отмена над чужим экраном оставляет этот экран;
  - после выбора по дубликату отмена ранее созданных позиций остаётся в
    баннере.
- **Нет ложного «Срок снят».** «Без срока» у задачи, у которой срока нет,
  показывает карточку без баннера.
- **Пустой текст не тратит LLM.** Текст внешнего capture из одних
  управляющих символов отклоняется `422` до квоты и до вызова LLM.
- **Шаги тика независимы.** Ошибка одного шага тика планировщика не
  обрывает остальные шаги этого тика.
- **Snooze без привязки считается устаревшим.** Snooze без привязки к
  вхождению срока отменяется на ближайшем тике. Переходное правило 0005
  удаляется из спеки и кода. Миграции нет.

## Capabilities

### New Capabilities

<!-- Нет. -->

### Modified Capabilities

- `telegram-rich-ui`:
  - баннер при несобираемом экране;
  - отмена прямого добавления;
  - быстрый срок «Без срока» у задачи без срока.
- `llm-capture`: текст без печатаемых символов отклоняется до LLM.
- `notifications-reminders`:
  - независимые шаги тика;
  - из «Snooze следует за сроком задачи» удаляется переходное правило для
    snooze без привязки.

## Impact

- Код:
  - `src/telegram/bot/mod.rs` (`present_to`);
  - `src/telegram/bot/shopping.rs` (`added_undo`, `present_after_undo`);
  - `src/telegram/bot/model.rs` (`Action::AddedUndo`, `addition_rows`,
    действия выбора дубликата);
  - `src/telegram/capture_worker.rs` (сборка баннера);
  - `src/telegram/bot/card.rs` (`set_due`);
  - `src/http/api/capture/mod.rs`;
  - `src/jobs/scheduler.rs`, `src/jobs/notice.rs` (`reminder_stale`).
- БД, HTTP API и `tasklerq-ha` не меняются.
- Документация: `docs/domain-model.md` (описание `origin_key`).
