# Design

## Context

Опирается на 0013 (консоль, сессии, Origin-проверка, askama, системный актор) и
0014 (ссылка-claim с `household_id`). Операции уже есть в `src/admin/mod.rs`:
`list_households` → `HouseholdSummary`, `create_household`,
`delete_household`, `add_user`, `create_token`, `revoke_token`,
`list_tokens`, `queue_stats` → `QueueStats`, `export`, а также
`select_household` для правил `single`/`multi`. Ошибки домена переводятся в
текст `admin::describe`.

## Goals / Non-Goals

**Goals:**

- Паритет с `tasklerq admin` без второй реализации правил.
- Одинаковый результат CLI и консоли для одних и тех же действий: те же
  правила, тот же формат выгрузки. Аудит выгрузки, которого у CLI сейчас нет,
  добавляется в общую функцию и появляется в обоих путях.

**Non-Goals:**

- Удаление участников, смена ролей и передача владения — остаются в боте
  (у CLI их тоже нет).
- Просмотр журнала аудита с фильтрами (v0.5).
- Повтор и очистка dead-letter из консоли.

## Decisions

### 1. Консоль — тонкий слой над `src/admin`

Каждый обработчик консоли разбирает форму, вызывает функцию `admin::*` и
рендерит результат или текст `admin::describe(error)`. Правила (единственность
household в `single`, второй владелец, Telegram ID в другом household, срок
токена до 3650 дней) живут только в `src/admin` и домене; тесты консоли
проверяют, что отказ доходит до страницы, а не повторяют сами правила. Если для
списка участников household нет функции, она добавляется в `src/admin` поверх
существующего репозитория `members`, а не пишется SQL в консоли.

### 2. Маршруты по household

`/admin/households`, `/admin/households/{id}` (участники, токены, claim,
выгрузка). В `single` пункт меню ведёт сразу на единственный household через
`select_household`; в `multi` — на список. Идентификатор household в пути —
UUIDv7, проверяется на существование и активность; удалённый household → `404`.

### 3. Подтверждения

Опасные действия — двухшаговые: GET показывает форму подтверждения, POST
выполняет действие только с полем подтверждения (название household,
совпадающее с текущим без учёта крайних пробелов; для токена — поле
`confirm=yes` из формы подтверждения). Это защита от случайного нажатия, а не
от подделки запроса: от CSRF защищает точная сверка `Origin` из 0013.

`admin::revoke_token(pool, token_id)` не проверяет household, поэтому консоль
перед отзывом сверяет, что токен принадлежит household из пути (иначе `404`):
иначе на странице одного дома можно было бы отозвать токен другого.

### 4. Выгрузка

`admin::export` получает запись события `household_exported` (новое
значение `audit_event_type`, миграция) с системным актором и идентификатором
household без содержимого — так событие пишут и CLI, и консоль. Обработчик
вызывает `admin::export` и отдаёт результат как
`application/json` с `Content-Disposition: attachment;
filename="tasklerq-<id>-<дата>.json"` и `Cache-Control: no-store`. Формат
совпадает с CLI, потому что функция одна; тест сравнивает выгрузки CLI и консоли
без поля времени. Право `0600` на файл здесь неприменимо — файл сохраняет
браузер; документация предупреждает, что выгрузка содержит личные данные.

### 5. Очереди

Страница рендерит `QueueStats`, htmx перезапрашивает фрагмент раз в 10 секунд.
Возраст самого старого готового обновления сравнивается с
`QUEUE_READY_LAG_SECONDS` и выделяется при превышении — тот же порог, что у
readiness.

### 6. Маскирование Telegram ID

В списках показываются последние четыре цифры: этого достаточно, чтобы
отличить участников, и меньше раскрытие при показе экрана. Полный Telegram ID
вводится только при добавлении участника.

## Risks / Trade-offs

- [Выгрузка оседает в папке загрузок браузера] → предупреждение на странице и в
  документации; событие выгрузки в аудите.
- [Расхождение текстов отказов CLI и консоли] → оба берут `admin::describe`.
- [Длинный список household в `multi`] → семейный масштаб; пагинация не
  нужна, при необходимости добавится без изменения спеки.
