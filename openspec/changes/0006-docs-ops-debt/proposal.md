# Proposal

## Why

Три проблемы эксплуатации и документации, которые не требуют продуктовых
решений.

1. **CI на `main` красный с 2026-11-05.** Job `audit` (`rustsec/audit-check`)
   на push пытается создать check run, а у job нет прав на это: «Resource not
   accessible by integration». На PR этот путь не срабатывает, поэтому
   поломку никто не видит.
2. **Откат тегом не работает.** Требование «Обновления и откат» обещает
   откат на предыдущий образ без потери данных. На деле после любой новой
   миграции предыдущий образ не стартует: `migration <номер> was previously
   applied but is missing in the resolved migrations`. Остаётся только
   restore backup, а он теряет всё, что записано после backup.
3. **`docs/telegram-ux.md` после 0005 описывает групповой snooze неверно.**
   Правило «snooze следует за сроком» там не описано.

## What Changes

- Job `audit` в CI вызывает `cargo audit` напрямую вместо
  `rustsec/audit-check`. Пропадают check run, лишние права и runtime Node 20.
- `serve`, `migrate` и `seed` запускаются на базе, где применены миграции,
  которых нет в образе. Такие версии не считаются ошибкой и перечисляются в
  предупреждении в логе. Откат тегом работает, если **целевой** образ уже
  содержит это изменение и схема совместима по правилу expand/contract. Для
  v0.1.0 и других образов без этого изменения действует прежний порядок
  через restore.
- `docs/deployment.md` §12 и §16.10 описывают новый порядок отката. Для
  отката на образ без миграции 0012 добавляется шаг сброса слота вхождения
  из design 0004. Неверная фраза про `RUST_LOG=tasklerq=debug` в §20
  исправляется.
- `docs/telegram-ux.md`:
  - формулировка про «Отложить все на час» в разделе сводного сообщения
    исправляется;
  - в разделе напоминания появляется правило отмены snooze при смене
    вхождения срока.

### Modified Capabilities

- `deployment-operations`: добавлено требование «Запуск на схеме с более
  новыми миграциями». Оно дополняет «Обновления и откат»: предыдущий образ
  запускается, а неизвестные ему миграции только перечисляются в логе.

## Impact

- `src/storage/migrations.rs`: `MIGRATOR` и `run()`. Все три вызова
  (`serve`, `migrate`, `seed` в `src/main.rs`) идут через `run()`, отдельных
  правок не нужно.
- Readiness не меняется: `all_applied()` проверяет только встроенные версии.
- Тест: `tests/migrations.rs`, запуск CLI `migrate` на базе с лишней версией.
- CI: `.github/workflows/ci.yml`, job `audit`.
- Документация: `docs/deployment.md`, `docs/telegram-ux.md`.
- HTTP API, схема БД и поведение бота не меняются.
