# Proposal

## Why

Пространство (household) на живой инсталляции было создано командой
`admin household create`, без владельца. Позже бот на `/start` не нашёл
Telegram-пользователя и создал второе пространство, никак не связанное с первым.
В итоге бот писал задачи в новое, а Home Assistant читал старое. У проблемы три
корня:

- два пути создания с разными инвариантами;
- нет правила «одно пространство на инсталляцию»;
- бот при первом контакте не смотрит на состояние инсталляции.

Кроме того, бот публичный, и сейчас любой незнакомец, написавший ему, создаёт
себе пространство на чужом сервере. Продукт заявлен как одно семейное
пространство, поэтому этот инвариант нужно закрепить до релиза `v0.1.0`.

## What Changes

- Добавляется режим размещения `TENANCY_MODE` со значениями `single` (по
  умолчанию) и `multi`. В `single` активным может быть не больше одного
  household. Ни бот, ни CLI не создают второе. Проверка единая для обоих путей
  и сериализована.
- **BREAKING:** в `single` бот создаёт household только на пустой инсталляции.
  Если пространство уже есть, неизвестному пользователю без приглашения бот
  отвечает «попросите приглашение» и новое пространство не создаёт. Режим
  `multi` сохраняет текущее поведение и в этом изменении не прорабатывается.
- Если household есть, но у него нет владельца, бот не передаёт его
  автоматически. Он показывает точную CLI-команду `admin user add`, в которую
  уже подставлен Telegram ID пользователя. Механизма «забрать пустое
  пространство» нет.
- Добавляется необязательная переменная `BOOTSTRAP_OWNER_TELEGRAM_ID`. Если она
  задана, на пустой инсталляции онбординг может пройти только этот Telegram ID.
  Если не задана, владельцем становится первый написавший, а при старте в лог
  пишется предупреждение.
- Если в режиме `single` при старте найдено больше одного активного household,
  сервис деградирует:
  - он стартует, пишет error в лог и предупреждение в `/health/ready`;
  - существующие пользователи работают как раньше;
  - создание новых пространств запрещено;
  - новые пользователи получают ответ «требуется вмешательство администратора».
- `admin household create` получает необязательные `--owner-telegram-id` и
  `--owner-name`, так что пространство вместе с владельцем создаётся одной
  командой. Добавляются `admin household list` и
  `admin household delete --household <id> [--yes]`. В `multi` флаг
  `--household` обязателен для команд, которые работают с household.
- В настройках бота появляется экран «Интеграции», доступный только владельцу:
  - список API-токенов household (имя, префикс, области, последнее
    использование);
  - отзыв токена с подтверждением;
  - выпуск токена для Home Assistant с областями
    `ha:read,ha:write,capture:write`.

  Токен показывается один раз отдельным сообщением под спойлером. Кнопка «Я
  сохранил» удаляет это сообщение. Открытое значение токена не сохраняется ни
  в outbox, ни в состоянии экранов.
- В `docs/deployment.md` и `docs/home-assistant.md` первый запуск описывается
  через бот. CLI-путь остаётся для headless-режима и bootstrap одной командой.

### Вне рамок

- Проработка режима `multi` (SaaS, мультитенантность) сверх текущего поведения.
- Слияние двух household и перенос данных между ними.
- Автоматическое удаление сообщения с токеном по таймеру.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Основные спецификации пока лежат в дельтах `0001-foundation`. Это изменение
MUST быть архивировано после `0001-foundation`.

- `identity-sharing`: первый запуск учитывает состояние инсталляции,
  `BOOTSTRAP_OWNER_TELEGRAM_ID` и household без владельца. Добавляется
  требование о режиме размещения и единственности household.
- `deployment-operations`: новые переменные `TENANCY_MODE` и
  `BOOTSTRAP_OWNER_TELEGRAM_ID`; команды `household create --owner-telegram-id`,
  `household list` и `household delete`; обязательный `--household` в `multi`;
  предупреждение о деградации в `/health/ready`.
- `security-privacy`: владелец выпускает и отзывает API-токены в Telegram;
  открытое значение токена не сохраняется после доставки.

## Impact

- **Код:**
  - `src/config` — новые параметры;
  - `src/storage/repositories/households.rs` — единая точка создания под
    advisory lock, проверка режима;
  - `src/admin` и `src/main.rs` — новые команды и флаги;
  - `src/telegram/bot/onboarding.rs` и `forms` — ветвление первого контакта;
  - `src/telegram/bot/settings.rs` и `model.rs` — экран «Интеграции»;
  - `src/telegram/outbox.rs` — затирание чувствительного payload после
    доставки;
  - `src/http/health.rs` — предупреждение о деградации.
- **БД:** схема и миграции не меняются. Индекс единственности не добавляется,
  потому что сломал бы `multi`.
- **API:** HTTP API не меняется. В `/health/ready` появляется необязательное
  поле `warnings`.
- **Эксплуатация:** на текущей инсталляции два household. После обновления
  сервис стартует в деградированном режиме. Починка:
  1. выпустить токен для household с владельцем;
  2. переподключить HA;
  3. удалить лишнее пространство командой `admin household delete`.
- **Связь с 0001:** задача 8.7 из `0001-foundation` (`household create/list`)
  частично покрывается этим изменением.
