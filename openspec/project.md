# Tasklerq — проект

## Обзор

Tasklerq — семейный сервис для ведения задач и списков покупок. Он объединяет
Telegram-бота с RichMessage-интерфейсом, календарь задач и Home Assistant, а
также разбор свободного текста через LLM, встроенную в Home Assistant.

Проект рассчитан на одну семью: несколько Telegram-аккаунтов, общие списки,
назначение задач и единое пространство household. Основной интерфейс —
приватный чат с ботом; Home Assistant показывает те же данные через нативные
сущности `todo` и `calendar`.

## Проблема

Семейные задачи и покупки обычно распределены между мессенджерами, заметками,
календарями и голосовыми командами. В результате:

- договорённости теряются в переписке;
- списки покупок существуют в нескольких копиях;
- Home Assistant не видит домашние задачи;
- добавить задачу «на бегу» слишком долго;
- несколько членов семьи не могут удобно работать с одним списком.

Tasklerq решает это, давая одну точку входа в Telegram, общее хранилище в
PostgreSQL и двустороннюю интеграцию с Home Assistant.

## Видение

1. Любой член семьи отправляет боту обычную фразу: «завтра в 18:00 позвонить
   маме, купить молоко и хлеб».
2. LLM в Home Assistant разбирает фразу в структурированный черновик.
3. Бот показывает черновик с кнопками; пользователь подтверждает или правит.
4. Задача появляется в общем календаре и в Home Assistant, покупка — в общем
   списке покупок.
5. Ту же фразу можно сказать голосовому ассистенту Home Assistant или передать
   автоматизацией: Tasklerq создаёт элементы сразу, без Telegram и без
   подтверждения в боте.
6. Напоминания приходят в Telegram, а домашние автоматизации могут использовать
   данные Tasklerq через сущности Home Assistant.

## Цели MVP

- Приватный Telegram-бот с RichMessage: кнопки внутри сообщения, редактирование
  сообщений, навигация без спама.
- Задачи: название, описание, срок (дата или дата и время), приоритет, теги,
  подзадачи, исполнитель, повторение.
- Списки покупок: количество, единица измерения, отметка «куплено», очистка
  выполненных, несколько списков.
- Дополнительные пользовательские списки (shopping/checklist).
- Календарь задач: задачи со сроком, вседневные и со временем, повторяющиеся
  вхождения.
- Home Assistant: тонкий custom component с сущностями `todo` и `calendar`,
  синхронизация через REST API.
- LLM-разбор свободного текста через `ai_task.generate_data` Home Assistant
  (Google Gemini): черновик с подтверждением в Telegram и прямой capture из
  Home Assistant без участия бота (голос, автоматизация, HTTP API).
- Семья: один household, роли owner/member, приглашения, общие списки,
  назначение задач.
- Напоминания, утренняя сводка, уведомления о назначении, тихие часы.
- Развёртывание через Docker Compose, внешний PostgreSQL, HTTPS-reverse-proxy,
  Telegram webhook.
- Безопасность по умолчанию: секрет webhook, токены API, изоляция household,
  защита от LLM-инъекций, отсутствие PII в логах.

## Не-цели MVP

- Веб-интерфейс и мобильное приложение.
- Нативная интеграция с CalDAV/ICS и телефонным календарём.
- Отдельные события и встречи, не являющиеся задачами.
- Голосовые сообщения в Telegram и собственное распознавание речи. Голосовой
  capture через Home Assistant (HA Assist) входит в MVP: распознавание выполняет
  HA, Tasklerq получает готовый текст.
- Групповые чаты Telegram.
- Магазины, цены, штрихкоды, рецепты и закупочные сценарии.
- Сложные правила повторения (исключения, «каждый второй вторник после
  праздника») и редактирование отдельного вхождения.
- Несколько household на пользователя, частные списки, сложная матрица прав.
- Публичный API для сторонних разработчиков и OAuth.
- Федерация, синхронизация между серверами, мультитенантность SaaS.
- HA add-on и ingress; проект рассчитан на HA Container и standalone Docker.

## Пользователи и роли

| Роль | Возможности |
| --- | --- |
| `owner` | Всё, что может member; управление household, участниками и приглашениями; создание, переименование, архивирование и удаление списков; удаление любых задач; удаление household. |
| `member` | Создание и редактирование задач и позиций, завершение, назначение, создание пользовательских списков; удаление собственных задач; настройки своего профиля. |

Пользователь идентифицируется по `telegram_user_id` в приватном чате. Паролей
нет: вход происходит через Telegram, приглашение — через deep link.

## Ключевые сценарии

1. **Быстрое добавление.** Пользователь пишет «купить молоко 2 л и хлеб», бот
   показывает черновик с двумя позициями, пользователь подтверждает.
2. **Планирование.** Пользователь создаёт задачу «оплатить интернет» на 5-е
   число с напоминанием за день; задача видна в календаре и Home Assistant.
3. **Семейная работа.** Владелец приглашает партнёра; оба видят списки, могут
   дополнять покупки и назначать задачи друг другу.
4. **Повторяющаяся задача.** «Каждый вторник вынести мусор» — бот напоминает
   каждую неделю, завершение переносит срок на следующее вхождение.
5. **Home Assistant.** Задача завершается из HA или из Telegram; изменение
   отражается в обеих системах.
6. **Свободный текст.** «Завтра в 18:00 позвонить маме, купить молоко» —
   LLM разделяет задачу и покупку, бот показывает черновик.
7. **Голос.** Пользователь говорит в HA Assist: «купи молоко и хлеб». Tasklerq
   создаёт две покупки сразу, без Telegram, и отвечает голосом «Добавил две
   покупки». При недоступности LLM создаёт одну позицию из исходного текста.
8. **Напоминание.** В 17:45 приходит сообщение с кнопками «Готово»,
   «Отложить на час», «Открыть».

## Архитектурные принципы

- **Rust и модульный монолит.** Один бинарник, axum + tokio + sqlx +
  PostgreSQL; фоновые задачи — воркеры в том же процессе. Микросервисы не
  оправданы масштабом семьи.
- **PostgreSQL — единственный source of truth.** Очереди Telegram, черновики,
  уведомления и outbox также хранятся в PostgreSQL; отдельный брокер не нужен.
- **Telegram webhook.** Публичный HTTPS-эндпоинт, проверка
  `X-Telegram-Bot-Api-Secret-Token`, сохранение обновления в очередь и быстрый
  ответ 200. Long polling — только для локальной разработки.
- **RichMessage — основной UI.** Кнопки находятся внутри rich-сообщения;
  переходы редактируют существующее сообщение. Адаптер инкапсулирует
  нестабильность Telegram Bot API.
- **LLM только разбирает.** LLM не пишет в базу, не вызывает инструменты и не
  выполняет действия. Rust валидирует результат, показывает черновик в Telegram
  и применяет его только после подтверждения; внешний capture с доверенного
  клиента применяется после серверной валидации в режиме `auto`.
- **Home Assistant — нативные сущности.** Тонкий Python-компонент отдаёт
  `todo`-сущности по спискам и одну `calendar`-сущность. MQTT discovery не
  поддерживает `todo`/`calendar`, поэтому компонент обязателен.
- **Один household.** Все списки общие; частных списков в MVP нет. Это
  осознанное упрощение модели прав.
- **Идемпотентность.** `update_id` Telegram, callback-токены, черновики,
  завершение задач и уведомления защищены от повторного применения.
- **Безопасность по умолчанию.** Каждый запрос авторизуется, каждый ресурс
  проверяется на принадлежность household, пользовательский ввод экранируется,
  секреты не попадают в логи.
- **Наблюдаемость.** Структурированные логи, request ID, health/readiness,
  метрики очередей, LLM и capture; текст сообщений в логи не пишется.
- **Русский UI, английский код.** Интерфейс, документация и сообщения бота —
  на русском; идентификаторы, схема БД, API и код — на английском.

## Ограничения

- **Целевая среда — Synology NAS `192.168.10.110`** (`StellaLupus-NAS`),
  Docker/Container Manager, SSH-порт 2122. Развёртывание — Docker Compose.
- **Home Assistant Container (Docker), версия `2026.10.4`.** Нет Supervisor,
  add-on и ingress; контейнер `homeassistant` работает в `network_mode: host`,
  конфиг — `/volume2/docker/homeassistant`, HACS установлен. Компонент
  устанавливается в `custom_components` через HACS или вручную.
- **PostgreSQL уже существует на сервере пользователя.** Контейнер
  `postgres:18-alpine`, сеть `shared-db`, host-порт `15433`; Tasklerq
  подключается внутри сети как `postgres:5432`. Tasklerq не должен требовать
  SQLite и не должен управлять сервером БД; параметры подключения задаются
  через окружение.
- **Публичный домен и TLS.** Telegram webhook требует валидный HTTPS; домен
  `tasklerq.stellalupus.ru` указывает на NAS, TLS и маршрутизация — через
  Synology DSM Reverse Proxy. Host-порт Tasklerq — `127.0.0.1:18080`
  (`8080` занят Zigbee2MQTT), внутренний порт контейнера — `8080`.
- **Google Gemini через Home Assistant.** Прямой вызов Gemini из Rust не
  планируется: LLM доступна как AI Task `ai_task.google_ai_task_2`; модель
  выбирается в HA. HA → Tasklerq: `http://127.0.0.1:18080`; Tasklerq → HA:
  `http://host.docker.internal:8123` или `http://192.168.10.110:8123`.
- **Часовой пояс household — `Europe/Moscow`.** Исходный текст LLM-черновика
  (`raw_text`) хранится 30 дней; LLM-квота — 200 разборов в сутки на household.
- **Telegram-бот — `@tasklerqbot`.** Deep links приглашений:
  `https://t.me/tasklerqbot?start=<code>`. Бот — основной UI, но не обязательный
  транспорт создания: capture из Home Assistant работает при недоступном боте.
- **Capture без Telegram — первоклассный режим.** `POST /api/v1/capture`
  принимает текст от HA Assist, автоматизаций и других внешних клиентов;
  `source` и `mode` (`auto`/`draft`) задаёт вызывающая сторона. Сервис
  `tasklerq.capture` в HA-компоненте — рекомендуемый путь для голоса.
- **Headless-режим.** `TELEGRAM_MODE=disabled` позволяет запускать Tasklerq без
  бота и без `TELEGRAM_BOT_TOKEN`: остаются HTTP API, HA-компонент и capture.
- **Резервное копирование — Synology Hyper Backup на внешний диск.** Локальные
  дампы PostgreSQL хранятся 14 дней, затем выносятся Hyper Backup.
- **Масштаб семьи.** Один экземпляр сервиса, до ~10 пользователей, до ~10 000
  активных задач; тяжёлая горизонтальная масштабируемость не требуется.
- **Telegram Bot API RichMessage.** API молодой и может меняться; нужен
  изолирующий адаптер и деградация до обычных сообщений.
- **Часовые пояса.** Хранение в UTC, отображение в часовом поясе пользователя;
  повторения считаются по локальному «настенному» времени.
- **Русский язык MVP.** Мультиязычность не входит в первую версию, но строки
  не должны быть захардкожены в бизнес-логике.

## Критерии успеха

- Член семьи может добавить задачу или покупку из Telegram менее чем за 15
  секунд, включая подтверждение черновика.
- Голосовая команда в HA Assist создаёт задачу или покупку без Telegram; при
  недоступности LLM создаётся хотя бы одна позиция из исходного текста.
- Задача, созданная в Telegram или голосом, появляется в Home Assistant и в
  календаре не позднее чем через 60 секунд (при штатном polling).
- Завершение задачи в HA отражается в Telegram, и наоборот.
- Повторяющаяся задача не создаёт дублей напоминаний после перезапуска сервиса.
- Все сценарии из `openspec/specs/` покрыты тестами или явной ручной проверкой.
- Секреты не попадают в репозиторий, логи и diagnostics; webhook отклоняет
  запросы без корректного секрета.
- Развёртывание воспроизводится по документации на чистом сервере с Docker.
- Владелец может пригласить члена семьи и удалить его доступ без ручных
  запросов к базе.

## Словарь

| Термин | Значение |
| --- | --- |
| **Household** | Семейное пространство: участники, списки, задачи, настройки. |
| **Список** | Контейнер задач (`tasks`), покупок (`shopping`) или чек-листа (`checklist`). |
| **Задача** | Элемент списка `tasks` со сроком, приоритетом, тегами, подзадачами и исполнителем. |
| **Позиция** | Элемент списка покупок или чек-листа. |
| **Вхождение (occurrence)** | Конкретная дата/время повторяющейся задачи. |
| **Черновик (draft)** | Результат LLM-разбора, ожидающий подтверждения пользователя. |
| **Capture** | Процесс превращения свободного текста в элементы: из Telegram — через черновик, из HA/API — сразу (`auto`) или в черновик (`draft`). |
| **Внешний capture** | Capture без Telegram: HA Assist, автоматизация, прямой HTTP API. |
| **Голосовой capture** | Внешний capture, где HA Assist распознал речь и передал текст в Tasklerq. |
| **Auto-режим** | Применение валидированного разбора сразу, без подтверждения в боте; ответ содержит `speech` и `capture_id` для отмены. |
| **Fallback-создание** | Создание одной позиции из исходного текста без LLM, если разбор недоступен. |
| **RichMessage** | Сообщение Telegram с HTML/блоками и кнопками внутри содержимого. |
| **AI Task** | Сущность Home Assistant `ai_task`, выполняющая структурированный запрос к LLM. |
| **Outbox** | Таблица исходящих сообщений для надёжной доставки в Telegram. |
