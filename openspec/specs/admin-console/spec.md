# admin-console Specification

## Purpose

Консоль оператора инсталляции: веб-интерфейс на отдельном, закрытом по
умолчанию listener, через который администратор настраивает Tasklerq без правки
окружения — учётная запись, первый вход, сессии, хранилище настроек и мастер
первого запуска.

## Requirements

### Requirement: Отдельный listener консоли

Система SHALL обслуживать консоль только на отдельном адресе `ADMIN_BIND_ADDR`
(по умолчанию `0.0.0.0:8081`). Публичный listener MUST NOT обслуживать ни один
маршрут консоли, включая страницы входа и восстановления. Значение `disabled`
MUST выключать консоль; невалидный адрес MUST приводить к ошибке запуска.

#### Scenario: Консоль на публичном адресе

- **WHEN** на публичный listener приходит запрос `GET /admin` или
  `GET /admin/login`
- **THEN** ответ — `404`
- **AND** ответ не отличается от ответа на любой неизвестный путь

#### Scenario: Консоль выключена

- **WHEN** сервис запускается с `ADMIN_BIND_ADDR=disabled`
- **THEN** сервис стартует без второго listener
- **AND** публичный API и capture работают

#### Scenario: Невалидный адрес консоли

- **WHEN** `ADMIN_BIND_ADDR=localhost:abc`
- **THEN** сервис отказывается запускаться
- **AND** сообщение называет параметр и ожидаемый формат

### Requirement: Учётная запись администратора

Система SHALL поддерживать одну учётную запись администратора инсталляции с
именем и паролем. Учётная запись MUST NOT быть связана с участниками household
и MUST NOT требовать Telegram. Пароль MUST содержать от 12 до 1024 символов и
MUST храниться только как хеш медленной функции с солью. Действия консоли MUST
выполняться от системного актора.

#### Scenario: Пароль хранится хешем

- **WHEN** администратор задаёт пароль
- **THEN** в базе хранится только хеш с параметрами функции
- **AND** пароль не попадает в лог, аудит и ответы

#### Scenario: Слишком короткий пароль

- **WHEN** администратор задаёт пароль из 8 символов
- **THEN** консоль отклоняет его и называет минимальную длину
- **AND** учётная запись не создаётся и не меняется

#### Scenario: Действие консоли в журнале

- **WHEN** администратор выпускает в консоли API-токен
- **THEN** событие токена записано с системным актором, а не с участником
  household

### Requirement: Смена пароля

Консоль SHALL позволять сменить пароль после ввода текущего. Смена пароля MUST
завершать все сессии администратора, кроме текущей, и MUST записываться в
аудит.

#### Scenario: Смена пароля

- **WHEN** администратор вводит верный текущий и новый пароль
- **THEN** пароль меняется
- **AND** сессии на других устройствах недействительны

#### Scenario: Неверный текущий пароль

- **WHEN** администратор вводит неверный текущий пароль
- **THEN** пароль не меняется
- **AND** попытка учитывается в ограничении частоты

### Requirement: Setup-код первого входа

Пока учётной записи нет, консоль SHALL принимать только setup-код. Код MUST
содержать не менее 128 бит случайности, MUST быть одноразовым и MUST храниться
в базе только хешем. При старте без учётной записи и с включённой консолью
система MUST выпускать новый код и выводить в лог код и порт консоли.
Команда `tasklerq admin setup-code` MUST выпускать новый код.

#### Scenario: Код в логе при первом старте

- **WHEN** сервис стартует, а учётной записи администратора нет
- **THEN** лог содержит setup-код и порт консоли
- **AND** прежний неиспользованный код перестаёт действовать

#### Scenario: Учётная запись уже есть

- **WHEN** сервис стартует, а учётная запись существует
- **THEN** setup-код не выпускается и в лог не выводится

#### Scenario: Неверный код

- **WHEN** на странице первого входа введён неверный код
- **THEN** консоль отказывает без подсказки о причине
- **AND** отказ записывается в аудит и учитывается в ограничении частоты

#### Scenario: Код использован

- **WHEN** по верному коду создана учётная запись
- **THEN** повторный ввод того же кода отклоняется
- **AND** страница первого входа больше не доступна

#### Scenario: Код из CLI при существующей учётке

- **WHEN** администратор выполняет `tasklerq admin setup-code`, а учётная запись
  уже есть
- **THEN** команда завершается ошибкой и предлагает `reset-password`

### Requirement: Вход и сессии

Система SHALL выдавать после входа сессию в cookie с флагами `HttpOnly` и
`SameSite=Strict`; флаг `Secure` MUST ставиться, если запрос пришёл по HTTPS
через прокси из `ADMIN_TRUSTED_PROXIES`. В базе MUST храниться только хеш токена
сессии. Сессия MUST истекать через 7 дней без активности и через 30 дней после
входа. Выход MUST завершать сессию на сервере. Страницы консоли MUST запрещать
кеширование и встраивание во фреймы.

#### Scenario: Успешный вход

- **WHEN** администратор вводит верные имя и пароль
- **THEN** консоль выдаёт cookie сессии и открывает главную страницу
- **AND** вход записывается в аудит

#### Scenario: Неактивная сессия

- **WHEN** сессией не пользовались 7 дней
- **THEN** следующий запрос перенаправляется на страницу входа

#### Scenario: Выход

- **WHEN** администратор нажимает «Выйти»
- **THEN** сессия удаляется на сервере
- **AND** повтор запроса со старой cookie перенаправляется на вход

#### Scenario: Заголовки страниц

- **WHEN** консоль отдаёт любую HTML-страницу
- **THEN** ответ содержит `Cache-Control: no-store` и запрет встраивания во
  фреймы

### Requirement: Защита изменяющих запросов консоли

Система SHALL принимать изменяющие запросы консоли, включая вход, ввод
setup-кода и восстановление, только с заголовком `Origin` (или, при его
отсутствии, `Referer`), который совпадает с origin запроса по схеме, хосту и
порту. Origin запроса MUST определяться по `Host` и схеме соединения, а через
прокси из `ADMIN_TRUSTED_PROXIES` — по его заголовкам. Запрос без совпадения
MUST отклоняться с `403` без изменения данных.

#### Scenario: Запрос с чужого сайта

- **WHEN** изменяющий запрос к консоли приходит с `Origin: https://evil.example`
  и действующей cookie
- **THEN** ответ — `403`
- **AND** настройки не меняются

#### Scenario: Соседний сервис на том же хосте

- **WHEN** консоль открыта на `http://nas:18081`, а изменяющий запрос приходит
  с `Origin: http://nas:8123`
- **THEN** ответ — `403`

#### Scenario: Вход с чужого сайта

- **WHEN** форма входа отправлена с чужим `Origin`
- **THEN** ответ — `403`
- **AND** сессия не выдаётся

### Requirement: Ограничение частоты входа

Система SHALL ограничивать неудачные попытки входа, ввода setup-кода, ввода
текущего пароля и восстановления: не более 5 за 15 минут на клиента, отдельно
для каждого вида попытки. Клиент MUST определяться по адресу соединения, а
`X-Forwarded-For` MUST учитываться только от прокси из `ADMIN_TRUSTED_PROXIES`.
Сверх лимита MUST возвращаться `429` без проверки пароля или кода. Неудачные
входы MUST учитываться в пороге уведомления об отказах аутентификации.

#### Scenario: Перебор пароля

- **WHEN** с одного адреса за 15 минут шестой раз вводится неверный пароль
- **THEN** ответ — `429`
- **AND** пароль не проверяется
- **AND** событие превышения лимита записывается в аудит

#### Scenario: Подмена X-Forwarded-For

- **WHEN** `ADMIN_TRUSTED_PROXIES` пуст, а клиент из LAN меняет
  `X-Forwarded-For` в каждой попытке
- **THEN** все попытки считаются попытками одного клиента по адресу соединения

#### Scenario: Удачные входы не расходуют лимит

- **WHEN** администратор четыре раза подряд успешно входит с одного адреса
- **THEN** пятый вход с верным паролем проходит

### Requirement: Восстановление доступа

Команда `tasklerq admin reset-password` SHALL выпускать одноразовую ссылку
восстановления сроком 15 минут и выводить её путь; в базе MUST храниться только
её хеш. Открытие ссылки MUST NOT расходовать её; ссылка MUST расходоваться
только при сохранении нового пароля. Смена пароля по ссылке MUST завершать все
сессии администратора.

#### Scenario: Восстановление через CLI

- **WHEN** администратор выполняет `tasklerq admin reset-password` и открывает
  выданную ссылку в течение 15 минут
- **THEN** консоль предлагает задать новый пароль
- **AND** после сохранения все прежние сессии недействительны

#### Scenario: Ссылка истекла

- **WHEN** ссылку открывают через 16 минут после выпуска
- **THEN** консоль сообщает, что ссылка недействительна
- **AND** пароль не меняется

#### Scenario: Предпросмотр ссылки

- **WHEN** ссылку открыли дважды без сохранения пароля
- **THEN** ссылка остаётся действительной до сохранения или истечения срока

### Requirement: Хранилище настроек

Система SHALL хранить настройки в базе на уровне инсталляции и на уровне
household. Значение настройки MUST определяться по порядку: окружение, затем
база, затем значение по умолчанию. Настройка, заданная окружением, MUST
показываться в консоли только для чтения с указанием источника. Значения
секретов MUST NOT показываться в консоли после сохранения.

#### Scenario: Значение из окружения

- **WHEN** заданы `LLM_PRIMARY_URL` и `LLM_PRIMARY_MODEL`, а в базе сохранена
  другая модель
- **THEN** действует значение из окружения
- **AND** консоль показывает поля слота только для чтения с источником
  «окружение»

#### Scenario: Секрет после сохранения

- **WHEN** администратор сохранил токен слота и снова открыл страницу слота
- **THEN** поле показывает, что токен задан, но не показывает его значение
- **AND** токен можно заменить или удалить

### Requirement: Шифрование секретов в базе

Система SHALL шифровать секретные настройки ключом `TASKLERQ_SECRET_KEY` с
проверкой целостности; шифротекст MUST быть привязан к имени настройки. Без
ключа сохранение секрета MUST отклоняться с объяснением. Если ключа нет или он
не подходит, сервис MUST запускаться, а группа настроек с нерасшифрованным
секретом MUST считаться ненастроенной целиком.

#### Scenario: Ключ не задан

- **WHEN** `TASKLERQ_SECRET_KEY` не задан и администратор сохраняет токен слота
- **THEN** консоль отказывает и объясняет, что нужен ключ шифрования
- **AND** несекретные поля слота можно сохранить

#### Scenario: Неверный ключ

- **WHEN** сервис запускается с ключом, которым токен основного слота не
  шифровался
- **THEN** сервис стартует
- **AND** основной слот считается ненастроенным, запросы к нему без токена не
  уходят
- **AND** консоль показывает токен как «не расшифровывается, введите заново»
- **AND** лог и readiness содержат предупреждение без значений

#### Scenario: Подмена шифротекста

- **WHEN** шифротекст одной настройки скопирован в строку другой настройки
- **THEN** расшифровка отклоняется
- **AND** группа этой настройки считается ненастроенной

### Requirement: Мастер первого запуска

После создания учётной записи консоль SHALL проводить администратора по шагам:
household (только в `single`, если его нет); LLM; токен для Home Assistant.
Шаги LLM и токена MUST допускать пропуск; шаг household MUST допускать пропуск,
только если Telegram включён. Мастер MUST продолжаться с первого незавершённого
шага после повторного входа и MUST NOT повторять завершённые шаги.

#### Scenario: Установка только с Home Assistant

- **WHEN** на пустой инсталляции в режиме `single` без Telegram администратор
  создаёт household, пропускает LLM и выпускает токен
- **THEN** household создан без владельца
- **AND** токен со scopes `ha:read`, `ha:write`, `capture:write` показан один
  раз
- **AND** в базе хранится только хеш токена

#### Scenario: Household создаст владелец в боте

- **WHEN** Telegram включён и администратор пропускает шаг household
- **THEN** household не создаётся
- **AND** первый допустимый пользователь проходит онбординг в боте, как раньше

#### Scenario: Household уже есть

- **WHEN** администратор впервые входит на инсталляцию, где household уже
  создан через бота
- **THEN** шаг household пропускается

#### Scenario: Возврат в мастер

- **WHEN** администратор закрыл консоль после шага household и вошёл снова
- **THEN** мастер открывается на шаге LLM

#### Scenario: Режим multi

- **WHEN** инсталляция работает в режиме `multi`
- **THEN** мастер не показывает шаги household и токена

### Requirement: Настройка LLM в консоли

Консоль SHALL позволять включить разбор и задать основной и резервный слоты
(адрес, модель, токен, таймаут, дополнительные параметры), таймаут соединения и
суточную квоту. Перед сохранением значения MUST проходить ту же валидацию, что
при запуске. Сохранённые настройки, включая квоту, MUST применяться без
перезапуска сервиса.

#### Scenario: Резервный слот наполовину

- **WHEN** администратор задаёт адрес резервного слота без модели
- **THEN** консоль отклоняет сохранение и называет недостающее поле
- **AND** действующие слоты не меняются

#### Scenario: Смена модели без перезапуска

- **WHEN** администратор меняет модель основного слота и сохраняет
- **THEN** следующий разбор идёт через новую модель без перезапуска процесса
- **AND** статус слота сразу становится «устарел»

#### Scenario: Смена квоты без перезапуска

- **WHEN** суточная квота исчерпана при значении 200, а администратор меняет её
  на 300
- **THEN** следующий разбор в тот же день выполняется без перезапуска

### Requirement: Состояние инсталляции в консоли

Главная страница консоли SHALL показывать версию, состояние readiness с
предупреждениями, режим размещения, число household, состояние Telegram и
статусы слотов LLM. Страница MUST NOT показывать секреты и пользовательский
контент.

#### Scenario: Непроверенный слот на главной

- **WHEN** основной слот не проходил проверку
- **THEN** главная страница показывает статус «не проверен» и ссылку на
  проверку слота
